## 4. 설계 가정 오류 (실측이 설계와 다른 곳)

1. **가시성 패스**: 설계의 0.17 ms 마이크로벤치는 깊이와 법선을 읽지 않았다. 깊이 + 수신 평면만으로 0.114 ms가 바닥이다(4K).
2. **요청 페이지 수**: texel ≤ footprint 규칙이면 4K에서 3,000~5,500 페이지다(설계는 800~1,500). 풀은 메가픽셀당 700 페이지(4K 약 370 MB +
   블록 64 MB)이고 소진 시 커진다.
3. **프록셀 적분**: 설계는 "F × 300 FLOP + F × 64 B"였다. 실제 프록셀 일은 의존 메모리 조회다(LUT 2개 + VSM 테이블 → 블록 → 텍셀). 게다가
   이 항이 이제 옛 공기 원근 볼륨까지 대신한다.
4. **셰이딩 조회**: 설계는 "프록셀 조회 1회"였다. 옛 API는 픽셀마다 3D 8회 + 파라미터 9 Load였고, 낮은 점유율의 셰이딩 커널에서
   1.12 ms였다. 새 공기 볼륨으로 고쳤다.
5. **클립맵 단 수**: 12단(텍셀 2 m까지)은 4K 약 1 km 너머 공기와 먼 지면에 맞는 단이 없다. 20단으로 늘렸다.
6. **규칙 (a)**: 움직인 캐스터가 모든 단을 다시 그리면 동적 장면(강체 1,024 + 캐릭터 256)에서 래스터 0.81 ms다(I 실측). 텍셀 누적 규칙으로 고쳤다.

- **구조**(3694e57, ef147c4, cd72dd6):
  - 각 VSM 단이 자기를 그린 태양 기저(64 B `VsmLevel`: 기저, 카메라 투영, 캐스터 높이 범위, 기저 id)를 갖는다.
  - 조회·표시·공기 걷기·래스터는 그 단의 기저를 쓴다. 수신점은 기저가 다른 단으로 갈 때만 다시 투영한다(정지 태양이면 숫자가 같다).

## 8. 정확한 다중 산란 원천표 J_ms (설계, 2026-09-25; 구현 중)

- **원인 [실측]**: ridge_sunset 하늘이 C 기준보다 −1/−1.7/−3 %(R/G/B) 어둡다. 검은 지면 장면에서 차수를 나눴다(`unx_gate_atmosphere_skyorders`, e2d5908).
  - 단일 산란은 S 모델/기준 0.999다.
  - 2차 이상은 0.80~0.94다. Hillaire 2020 Ψ_ms(등방 2차 + 기하급수)가 태양 쪽 시선에서 이방적인 다중 산란을 놓친다.
  - GPU 하늘은 모델과 0.5 % 안에서 같다(LUT 구현은 원인이 아니다).
- **바꿀 것**: Ψ_ms(h, μs) 2D를 J_ms(r, μ, μs, ν) 4D로 바꾼다. 다중 산란 원천은 σ_s로 나눈 값, 태양 조도 1당이다.
  - 구성: 차수 반복(Bruneton식). 단일 산란은 지금처럼 즉석 계산한다(캐스터 그림자 포함).
  - 표는 태양 방향과 무관하다. 매질·지면 알베도가 바뀔 때만 다시 만든다. 태양 속도 제한 없음과 충돌하지 않는다.
  - 원천 = (σ_R + σ_M)·Ĵ, Ĵ = (σ_R S_R + σ_M S_M)/(σ_R + σ_M), S_i = ∫ p_i(ω'·v) L_{≥1}(x, ω') dω'.
  - L_{≥1}은 직접 태양을 뺀 모든 입사광이다(지면 반사 포함). 지면 간접 조도 E_ind(μs)도 같이 만든다(하늘 뷰의 지면 항).
- **표**: (ν 16, μs 32, μ 64, r 32) = 1,048,576 텍셀 × RGBA16F = 8 MiB(Texture3D 512 × 64 × 32).
  - fp16 범위: 값 × 2^14로 저장한다. 박명 1e-6이 정규 범위에 든다.
  - 매핑: r은 Bruneton ρ/H, μ는 지평선 양쪽 반(각 32, 지평선 쪽 √ 조밀), μs는 0 근처 √ 조밀, ν는 √(θ/π)(태양 근처 Mie 조밀).
  - 매질 기록(params)과 E_ind 행은 투과율 LUT(RGBA32F)의 추가 행 2개로 옮긴다. 공개 조회는 색인만 받으므로 인터페이스는 그대로다.
- **조회 비용 [예상]**: 3D 선형 표본 2회(ν 두 블록) + ALU 약 30.
  - 지금은 RGBA32F Load 4회, 64 B다. 바뀌면 8 텍셀 × 8 B × 2, L2 적중이다.
  - 쓰는 곳: 프록셀 적분 substep, 하늘 뷰(태양이 움직이면 매 프레임), 공기 구간 함수.
  - 프레임 증가 [예상]: 4K 프록셀 적분 +0.01~0.03 ms, 하늘 뷰 +0.02 ms 안쪽. 구현 뒤 실측으로 바꾼다.
- **재구축 비용 [예상]**(매질이 바뀔 때만).
  - 1차 L1: 1M × 128 단계.
  - J_2: 1M × 방향 2048(Rayleigh 부분은 Fibonacci, Mie 부분은 HG 역CDF 층화) × 표본 2 = 4.3 G 표본.
  - J_3..J_N: 방향 256(L_{n−1}이 매끄럽다) = 0.54 G씩.
  - L_n: 1M × 64 × 2 = 0.13 G씩.
  - N = 6이면 약 7 G 표본, 18~24 ms다.
