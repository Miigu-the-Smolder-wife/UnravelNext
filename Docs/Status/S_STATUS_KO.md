## 4. 설계 가정 오류 (실측이 설계와 다른 곳)

1. **가시성 패스**: 설계의 0.17 ms 마이크로벤치는 깊이와 법선을 읽지 않았다. 깊이 + 수신 평면만으로 0.114 ms가 바닥이다(4K).
2. **요청 페이지 수**: texel ≤ footprint 규칙이면 4K에서 3,000~5,500 페이지다(설계는 800~1,500). 풀은 메가픽셀당 700 페이지(4K 약 370 MB +
   블록 64 MB)이고 소진 시 커진다.
3. **프록셀 적분**: 설계는 "F × 300 FLOP + F × 64 B"였다. 실제 프록셀 일은 의존 메모리 조회다(LUT 2개 + VSM 테이블 → 블록 → 텍셀). 게다가
   이 항이 이제 옛 공기 원근 볼륨까지 대신한다.
4. **셰이딩 조회**: 설계는 "프록셀 조회 1회"였다. 옛 API는 픽셀마다 3D 8회 + 파라미터 9 Load였고, 낮은 점유율의 셰이딩 커널에서
   1.12 ms였다. 새 공기 볼륨으로 고쳤다.
5. **클립맵 단 수**: 12단(텍셀 2 m까지)은 4K 약 1 km 너머 공기와 먼 지면에 맞는 단이 없다. 20단으로 늘렸다.
6. **규칙 (a)**: 움직인 캐스터가 모든 단을 다시 그리면 동적 장면(강체 1,024 + 캐릭터 256)에서 래스터 0.81 ms다(I 실측). 텍셀 누적 규칙으로 고쳤다.

- **구조**(3694e57, ef147c4, cd72dd6):

## 8. 정확한 다중 산란 원천표 J_ms (구현, 2026-09-26)

- **원인 [실측]**: ridge_sunset 하늘이 C 기준보다 −1/−1.7/−3 %(R/G/B) 어두웠다. 검은 지면 장면에서 차수를 나눴다(`unx_gate_atmosphere_skyorders`).
  - 단일 산란은 S 모델/기준 0.999다.
  - Hillaire 2020 Ψ_ms(등방 2차 + 기하급수)의 다중 산란이 기준의 0.80~0.94였다.
- **구조**(MsBuild.hlsl, AtmosphereCommon.hlsli): 차수를 반복하는 4D 원천표 Ĵ(r, μ, μs, ν). 원천 = (σ_R + σ_M)·Ĵ다. 태양 방향과 무관하고, 매질·지면 알베도가 바뀔 때만 다시 만든다.
  - 밀도(차수 n ≥ 2): (r, μs) 조각마다 L_{n−1}을 구면 조화(코사인 항, l ≤ 32)로 사영하고 Funk-Hecke로 평가한다. Rayleigh는 l ≤ 2로 정확하고, HG는 g^(L+1) = 6e-4까지 정확하다. 사영 격자는 지평선에서 나눈 √ 간격이다(지평선의 밝은 띠).
  - 저장: R16G16B16A16_UNORM ln Ĵ(0.08 % 단계), 로그 영역 보간이다. μs 축은 Catmull-Rom 4탭이고, 황혼에서 ln Ĵ가 태양 깊이의 제곱으로 떨어지는 것을 정확히 따른다. ν는 블록 2개를 섞고, μ와 r은 하드웨어 보간이다. 조회는 fetch 8회다.
  - 표 (ν 32, μs 64, μ 128, r 32), 텍스처 64 × 128 × 1024, 64 MiB. 한 프레임은 태양 근처 μs 열 약 4개만 읽는다(핫셋 약 4 MB).
  - μs 매핑: 지평선 양쪽 기울기 0.2(C1), 황혼 −8°에서 0.7°/노드, −23.6° 아래는 고정. ν: 각도 = π u^1.5.
  - 지면 간접 조도 E_ind(μs)와 매질 기록은 투과율 LUT의 추가 행 2개다(공개 조회는 색인만 받으므로 인터페이스는 그대로다).
  - 하늘 뷰: 단일 산란은 GL4점, Ĵ는 구간 경계에서 읽어 선형 보간한다(2차 정확).
- **정확도 [실측, AtmosphereTests]**: 복사휘도 기준이다(4,752 광선 × 하늘·공기 2 km·20 km, 카메라 1 m~30 km, 태양 −12°~89°).
  - 낮: 모든 축 2배 세밀·차수 +4·SH +12·격자 2배·걸음 4배에서 변화 ≤ 0.27 %다(한도 0.3 %).
  - J_2를 이중정밀 단일 산란의 구면 적분과 비교하면 0.46 %(태양 ≥ −8°), 2.7 %(더 깊음)다.

## 10. 계약: A3 FX 방출 입자 광원 (2026-09-27, 렌더 A와 합의; 구현은 주간 초기화 뒤)

- FX(엔진 2)는 빛 플래그 방출 행마다 레코드 하나를 쓴다. 장면 광원 버퍼의 GPU 꼬리 [N, N+F)에 gpu::Light 그대로다:
  점광원, cd × color, 렌더러 월드 좌표, range = 영향 반경, size.x = 퍼짐, castShadow 0 / shadowIndex 0xFFFF.
  개수 워드는 FrameResources::fxLightCount다. 꼬리 용량 F_max = 빛 플래그 행 수이고, 스트림 표가 바뀌면 core(A)가 재할당한다. 상한과 선택 단계는 없다.
- S: FroxelLists 루프 상한 = g_lightCount + F. 색인 ≥ N이면 그림자 슬롯이 없다. 비용 +14.4k·F 구 판정(4K 타일).
  제약: 16비트 목록 색인이므로 N + F_max ≤ 65,535(core가 검사, 넘으면 S가 32비트로 넓힌다).
- R: FX 광원의 세기 누적 분포(1패스, F 스레드). rtLocalLightSample은 격자 광원과 FX 목록을 세기 경계 비율로 고르고, FX는 log2 F 이진 탐색이다.
- M: 변경 없다.
- **정정(2026-09-27)**: 프록셀 목록 항목은 16비트이고 비트 15가 그림자 플래그다. 그래서 한도는 N + F_max ≤ 32,768이다(65,535가 아님). core가 반영했다(cefa25b).
- **구현 [실측, 하드웨어]**: S는 froxelLightTotal()을 쓰고 FroxelLists 루프 상한에 F를 더한다. 색인 ≥ N이면 그림자 플래그를 붙이지 않는다. FX 기록의 순서는 FrameResources::fxLights/fxLightCount 선언으로 정한다.
  R은 누적 분포 대신 **32개 묶음**을 쓴다(FxLightGroups.hlsl; 묶음마다 경계 구와 Σφ). 적중점에서 묶음 가중 Σφ/max(d², 1)으로 묶음을 고르고, 묶음 안에서는 정확한 중요도로 고른다.
  세기만 보는 분포는 멀리 있는 밝은 FX 광원 하나가 가까운 광원의 표본을 빼앗았다. 같은 시험에서 도달하는 15점이 FX 표본을 하나도 얻지 못했고, 평균 오차 10 %였다.
  시험: `unx_test_raytracing_fxlighthits`는 16,384 층화 선택의 평균 가중치를 정확한 합과 비교한다. 최악 오차는 묶음 1개 6.4e-4, 묶음 2개(40광원) 1.3e-3, 격자만 2.6e-4이고, 도달하는 점의 누락은 0이다.
  `unx_test_shadow_froxeltests` 1b: 도달하는데 목록에서 빠진 FX 광원 0, 그림자 플래그 0, 범위 밖 색인 0.
  비용: FX 광원이 없는 city 4K에서 GI 0.919 → 0.917 ms, 반사 1.974 → 1.962 ms. 쓰는 쪽(FX 모듈)이 들어오면 발광 장면에서 다시 잰다.
- **열린 결함(S)**: FroxelTests 2의 "shadowed air of local lights" 최대 노드가 앞서 돈 프레임 수에 따라 달라진다. 빈 프레임 2개만 더해도 656노드 중 1개가 5.1배 틀리고(평균은 1.4 %), 기본 순서에서는 0.056이다.
  VSM 국소 페이지 상태가 프레임에 따라 달라지는 것으로 보인다. 원인을 조사할 차례이고, 시험 1b는 이것을 가리지 않게 맨 끝에서 돈다.
