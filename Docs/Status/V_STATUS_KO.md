- 설계(2.1): 숲 V 1.34 ms(컬링·분류 0.16 + HiZ 0.02 + 대역 A 0.36 + 대역 B/C 0.80), 도시 0.70 ms. 모두 4K.
- **숲이 설계의 6.7배인 원인(설계 가정은 맞고 구현이 아직 없는 것):** 얇은 기하 LOD 보호 때문에 잎·풀잎은 단순화되지 않고(의도), 그것을 대신할 대역 C 집합체(복셀 브릭)가 아직 없다. 그래서 원거리 얇은 기하 1.6억 삼각형(대역 C 1.03억 + B 0.57억)을 원본 그대로 컬링·래스터한다. 대역 C가 들어오면 이 클러스터들은 브릭 노드로 바뀐다. 숲 비용은 브릭 구현 뒤에 다시 잰다.
- **도시의 고정 비용:** 컬링 0.116 ms는 데이터 비례항(설계식 0.001 ms)이 아니라 종속 패스 수(2단계 × (인스턴스·루트 + 트리 레벨마다 준비·노드 2개 + 그룹·클러스터·그리기 준비))에서 온다. 개선 후보: 지속 스레드 계층 순회(단계당 패스 2~3개). 숲 문제(브릭)를 먼저 푼다.
- **도시의 대역 B 비율(삼각형 91%) — 원인과 수정 [실측]:** 진단 카운터로 대역 B 삼각형 64,132개를 사유별로 셌다. 60,190개가 "평판, 계수 0"이었다. 원인은 두 가지다. ① 지형(열린 시트, 폭 68 m 이상)을 스침각으로 볼 때 `각 + asin(R/d) + 퍼짐 ≥ 90°`가 되어 계수가 0이 됐다. ② meshoptimizer 원뿔은 감김(winding)에 따라 달라서, 법선 퍼짐이 84°를 넘는 클러스터(엇갈린 카드)는 축이 0인 원뿔(cutoff 1)이 되고 NaN이 됐다.
  수정: 빌더가 클러스터마다 감김과 무관한 시트 축·퍼짐·slab(`clusterSheets`)을 내고, 평면 성분(퍼짐 5° 이내)은 방향 등급(팔면체 12×12 셀)별로 따로 DAG를 만든다(엇갈린 카드가 한 클러스터에 섞이지 않음). 컬링의 평판 계수는 두 경우로 나눈다. 폭 r ≤ 2R이면 cos(α + 퍼짐)이고, 원근의 cos α ≥ (눈과 slab 거리)/(d + R)다. r > 2R(넓은 시트: 지형)이면 폭 현(chord)의 단축 (눈과 slab 거리)/(d + R + r)이다.
  결과: 도시 A/B = 6,665/64,108 → **30,111/40,838**. 남은 B의 대부분은 나무 잎 카드(0.35 m, 임의 방향)이고, 그중 모서리에 가깝게 보이는 것은 설계상 B/C가 맞다. 대역 분류는 아직 그리기에 쓰지 않는다(`kBandMode = 0`).

## 알려진 한계·남은 일

1. **대역 C 브릭(최우선):** 16³ 브릭 베이크(밀도·법선 분포·알베도), terminal 얇은 그룹 위로 이어지는 브릭 계층(같은 DAG 절단 규칙: 브릭 복셀 크기 = 오차), 픽셀 광선 행진 → coverage fragment 1개. 설계 2.1 "대역 C" 행.
2. **대역 B coverage 층:** 보존 래스터 + 삼각형∩픽셀 정확 면적(`Coverage.hlsli`, M과 공유) + 32-부표본 마스크 + fragment append + 픽셀별 정렬. 대역 B → C 전환에 "픽셀당 가닥 > 2"(depth complexity) 기준 추가.
3. 알파 테스트 재질: GPU 장면이 텍스처를 아직 올리지 않아(`GpuScene`의 텍스처 번호 kNone) 알파 테스트 재질은 자르지 않고 그린다(로그 1회). 텍스처 업로드는 M의 텍스처 시스템과 함께(코어·M 조율).
4. 가파른 합성 지형(70° 경사, 1.5 m 능선)은 뒤집힘 규칙(모든 꼭짓점에서 원 표면과 같은 쪽)이 엄격해 거의 단순화되지 않는다. C의 실제 장면으로 다시 본다.
5. meshoptimizer 오차는 이차 오차 추정이라 점별 상한이 아니다: 원본 대비 편차 최대 1.53 px(1 px 초과 0.88%).
6. 스킨 인스턴스는 바인드 포즈 경계가 변형을 담지 않으므로 컬링하지 않는다(P3에서 뼈 경계로).
7. 인스턴스 셀 계층(설계 2.1의 64 m 셀 BVH) 미구현: 인스턴스 110만을 매 프레임 평면 순회한다.
