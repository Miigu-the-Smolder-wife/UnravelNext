# 게임 기능 설계 — 사용자 게임(3D 1인칭, 4K 165 fps, 가벼운 그래픽, 파괴·파편·유체)에 필요한 렌더러 기능 (설계 개정 세션, 2026-09-26~)

사용자 결정(2026-09-26 11:10, 계획서 14.4): 기능을 먼저 완성하고, 게임을 개발하면서 RPP-1 제작과 최적화를 한다. 이 문서는 빠진 기능을 사용자 게임 순서로 설계한다. 규율은 `ARCHITECTURE_KO.md`·`COVERAGE_REDESIGN_KO.md`와 같다: 기능마다 **정보량 → 비용식(실측 바닥 기준, [실측]/[예상] 표시) → 품질 정의와 정확 조건 → 최악 dispatch 시간 조건 → 소유 트랙 → 게이트**를 먼저 쓰고 구현한다. 부하·품질 정의는 낮추지 않는다. 설계 목표(RPP-1 부하 4K 6.06 ms, 게임 벤치는 같은 예산)는 그대로다. 인터페이스 변경은 `Requests/20260926_D_game_features.md`에 모아 코어가 INTERFACES에 반영한다.

## 0. 입자 렌더 패스와 유체 표현 (조율 확인 2026-09-26 11:25: UnravelNext에는 입자 렌더 패스가 아직 없다 — 시뮬레이션만 있다)

### 0.A 입자 렌더 패스 (소유 FX; 셰이딩 함수·합성 계약은 M)

**입력(요청 `20260925_FX_particle_render_rules.md` 그대로):** tick 패리티 상태 쌍(posAge·velocity) + 행 표, 렌더 프레임 시각 w의 보간(계속 산 입자 Hermite, 출생·사망 tick 선형), identity = (행, 출생 번호), 크기·색·알파·회전·uv·flipbook은 (프로그램, 이미터 매개변수, 나이)의 순수 함수로 렌더 시각에 평가, 볼륨 입자는 프록셀이 직접 tent-mass 평가(3b). 레코드 종류 4: **스프라이트**(빌보드·축 정렬 사각형, 텍스처·flipbook), **메시**(인스턴스 메시: 탄피·큰 파편), **리본**(궤적: 행마다 K ≤ 8점의 위치 이력 링을 FX 시뮬레이션이 출력 — 새 요구), **볼륨**(3b 레코드).

**정보량.** 픽셀마다 그 픽셀을 덮는 입자들의 깊이 순서와 각 입자의 (알파, 색, 조명). 매끄러운 매질 입자(연기·먼지·안개)는 대역이 낮아 1/4 해상도(4×4 블록)에서 정확하고, 불투명 경계 입자(불꽃 가장자리, 파편, 스파크)는 경계 픽셀만 전해상도 정보다(2.9의 기존 정의).

**단계(프레임마다, 전부 상수 그룹 일):**
1. **빈닝**: 보간 위치·크기로 화면 타일(8×8 셰이딩 타일; 프록셀 타일과 1:1이면 3b와 공유) 목록에 append(타일 항목 E = 입자 × 덮는 타일 수 ≈ 1~2 M @ RPP 622 k; 게임 벤치 ≤ 100 k live → ≤ 0.3 M). 타일 목록 상한(4 k)과 오버플로 비트.
2. **타일 정렬**(14.8 결정 1): groupshared에서 뷰 깊이(입자 중심) 정렬, 0.005 ns/항목 [DesignBench 정렬 단가].
3. **입자 조명(입자당 1회, 픽셀당이 아님)**: 태양 VSM 1탭(입자 중심, 크기의 반경으로 SMRT 없이 penumbra 대역 필터) + 타일 프로브 블록의 조도(12.3 groupshared, 입자 위치의 SH 평가) + 국소광 ≤ 8(12.4 닫힌 식, 구광원으로 입자 반경 포함) + 프록셀 투과율·in-scatter(입자 깊이에서 1탭 = 3b의 역방향 사용) → 입자당 ≈ 12탭 × 0.004~0.01 ns ≈ 0.1 ns → 622 k × 0.1 = **0.06 ms**. 정확 조건: 조명이 입자 한 개 안에서 매끄러움(매끄러운 매질의 정의); 법선 맵 스프라이트(파편 조각)는 픽셀당 N·L을 텍셀 법선으로 재평가(조도는 입자당 SH 그대로 = 정확).
4. **1/4 해상도 층 채우기**: 타일마다 정렬 목록을 앞→뒤로 알파 합성(premultiplied), 1/4 해상도 픽셀당 (색, 알파, 앞 깊이, 뒤 깊이) 기록. 채움 = Σ 스프라이트 면적/16: RPP 134 M/16 = 8.4 M 표본 × (텍스처 1탭 + 블렌드) 0.005 ns ≈ **0.04 ms**(2.9의 0.03과 같은 급).
5. **전해상도 재평가 픽셀** = (a) 층의 깊이 불연속 픽셀(2.9: 불투명 기하 깊이와 입자 층 깊이 범위가 교차하는 픽셀 → 픽셀마다 정확한 깊이 시험), (b) 불투명 경계 입자의 가장자리 픽셀(알파 1 → 0 경계, 텍스처 알파 마스크의 1/16 인구조사와 같은 E 규칙), (c) **coverage 층 fragment와 깊이가 겹치는 픽셀**(아래 합성 계약). 이 픽셀들은 입자를 **개별 레코드**로 M 합성 목록에 넣는다(16 B: 깊이, premultiplied 색, 알파; 마스크 = 전체). 수 [예상]: (a)+(b) 0.5 M px, (c) P_cov ∩ 입자 깊이 겹침(연기 속 풀: 숲에서 최대 1~2 M) × 겹치는 입자 수 2~4 → 레코드 2~8 M × 0.075 ns(M 합성 층당) = **0.15~0.6 ms**(RPP 상한; 게임 벤치는 풀이 없어 (a)(b)만 ≈ 0.05).
6. **합성 계약(M coverage 합성 4.5와의 관계)**: 픽셀의 최종 순서 = 불투명 → [coverage fragment ↔ 입자 레코드 깊이 순 병합] → 하늘. 1/4 층은 픽셀마다 **레코드 1개**(층의 앞 깊이, 누적 색·알파)로 목록에 들어가되, 그 픽셀에 fragment가 층의 [앞, 뒤] 깊이 안에 있으면 5(c)로 개별 레코드로 풀린다 — 따라서 병합 결과는 항상 정확한 깊이 순서다. fragment가 없는 픽셀(대부분)은 층을 불투명 위에 알파 합성하는 1탭(0.005 ns × 8.3 M = 0.04). 매끄러운 매질 입자는 프록셀에 누적되므로(3b) 모든 레코드가 자기 깊이의 프록셀 투과율을 곱해 자동으로 끼워진다(프록셀 슬라이스 해상도 안에서 정확).
7. **발광 입자의 광원 기여**: 이미터 단위로 합산한 방출(색·세기, 프레임마다 깜빡임 값)을 **구 광원 하나**로 국소광 목록에 넣는다(총구 섬광·불꽃: 그림자 있는 국소광 예산 안 — 매 프레임 전부 다시 그리기 기준이라 1프레임 광원도 같은 단가; 게임 벤치 광원 수십 이하). 반사·GI 안의 발광 형상: 평면 반사 뷰는 입자 패스를 같이 돌리므로 정확(A_r 비용 안); 광선 반사(G/M)는 입자를 보지 못한다 → **발광·큰 입자 시스템(캠프파이어·폭발, ≤ 4 k 입자/시스템)만 절차 AABB BLAS**(6.7의 집합체 TLAS와 같은 종류, 매 프레임 refit 0.01 ms)로 광선이 보게 하고 any-hit에서 알파 합성(광선당 any-hit ≤ 8 상한) — 그 밖의 입자는 광선에 없음을 3절 품질 표에 조건으로 적는다(광원 기여는 7의 구 광원으로 정확).
8. **굴절(열 아지랑이)**: 아지랑이 입자는 1/4 해상도 편향 벡터장 D(px)에 굴절률 기울기 기여를 누적(작은 각 근사에서 선형 합 = 정확 조건 |D| < 8 px)하고, 합성 때 그 입자 깊이보다 뒤의 배경 조회를 D만큼 옮긴다(앞 불투명 기하는 깊이 시험으로 제외). 비용 누적 0.01 + 합성 1탭 0.02.

**비용식 합계 [예상]:** 게임 벤치(≤ 100 k live, 광원 수십): 빈닝·정렬 0.01 + 조명 0.01 + 층 0.02 + 재평가 0.05 + 합성 0.04 + 발광 광원(국소광 행) + 굴절 0.03 ≈ **0.15 ms**; RPP 수변(622 k): 0.02 + 0.06 + 0.04 + 0.15~0.6 + 0.04 + 0.03 ≈ **0.35~0.8 ms** — 2.13 수변 행 0.32는 (c) 겹침 항이 없던 값이라 [예상] 상한이 0.5 오른다(기능 우선 결정에 따라 실측 뒤 예산 단계에서 다룸; 후보 = 겹침 픽셀에서 입자 레코드를 4×4 블록당 1개로 묶는 규칙의 정확 조건 = 블록 안 fragment 깊이가 모두 층 앞 또는 뒤).

**품질 정의·정확 조건(3절 표 갱신):** 깊이 순서 픽셀 정확(타일 정렬 + 병합); 매끄러운 매질 = 프록셀 대역 안 정확(기존 행); 스프라이트 조명 입자당 1회(조건: 입자 안 매끄러움); 경계·겹침 픽셀 = 개별 레코드 정확; 광선 반사는 지정 시스템만 봄(조건 기록); 열 아지랑이 |D| < 8 px. 게이트: C 경로추적기는 입자를 (구/사각 알파 카드 + 매질) 기하로 받아 같은 프레임 시각의 보간 상태를 렌더(C 도구 요청: 입자 상태 덤프 읽기).

**최악 dispatch:** 타일 목록 4 k 상한 + 오버플로 비트, 타일 그룹 상수, 재평가 레코드는 M 합성의 용량 C 안(초과 = OVERFLOW_COVERAGE).

### 0.B 유체 표현 (물리 Matter MPM → FX 표면 재구성 → 물 셰이딩 경로; 물리 설계 세션과 합의 대상)

- **경계**: 물리(2.14, 수변 250 k)는 tick마다 MPM 입자 위치·속도·재질 id를 GPU 버퍼 상태 쌍(입자 렌더와 같은 tick 패리티 규칙)으로 내놓는다. **FX**가 렌더 프레임 시각으로 보간해 표면을 재구성하고 그 표면을 **물 표면 패스와 같은 셰이딩 경로**(1절: M 유전체 재질 클래스 — 프레넬·굴절 탐색·흡수·코스틱 곱)로 그린다. 유체 안 매질(mediumMask, 프록셀 매질 = 유체)도 1절 (b)와 같은 규칙(유체 표면 메시가 닫혀 있을 때).
- **재구성**: 희소 격자(셀 = 입자 간격 h, 활성 셀 ≈ 입자/8 × 할로) 밀도 splat(입자당 27셀) → marching cubes(활성 셀만, 삼각형 ≤ 4/셀) → 정점·법선 버퍼(프레임 임시) → V의 런타임 단일 클러스터 메시(2절과 같은 경로)로 래스터. 비용 [예상] 250 k × 27 × 0.019 ns(원자) 0.13 + MC 100 k 셀 × 0.05 ns 0.005 + 래스터 200 k 삼각형 0.02 ≈ **0.15 ms**(수변). 정확 조건: 표면 = 밀도 등위면(입자 반경 r_p = 1.5 h) — MPM의 표면 정의 자체이므로 시뮬레이션에 대해 정확; 물방울 크기 < h인 비말은 표면이 아니라 **스프라이트 입자**(FX가 고립 입자를 0.A 스프라이트로 돌림).
- **광선**: 유체 표면은 프레임마다 바뀌는 메시라 BLAS를 매 프레임 빌드(200 k 삼각형 ≈ 0.1 ms [예상, R 실측으로 대체]) — 반사·굴절 fallback 광선이 필요할 때만(1절 규칙).
- **품질 정의**: 1.5의 물 행 그대로(같은 경로) + "재구성 등위면 = 시뮬레이션 표면 정의". 게이트: 게임 벤치 "유체" 케이스(양동이 쏟기 → 웅덩이, 300프레임) + C 경로추적기(재구성 메시를 유전체로).
- **소유**: 물리(상태 쌍·재질), FX(재구성·패스), M(재질 클래스), V(런타임 메시), R(BLAS 빌드), C(게이트).

## 1. 물 표면·수중

### 1.1 이미 있는 것과 빠진 것

있는 것(ARCHITECTURE 2.6·2.9·2.14): FFT 3 캐스케이드 512²(렌더 프레임 속도, 0.05 ms), 변위는 메시 셰이더, 표면 픽셀의 굴절(화면 공간 + 깊이차 흡수 해석 적분)과 반사(잔잔하면 평면 반사 카메라 래스터, 파도면 G/M 광선; 시차 조건 a × 1871 / d_r < 1 px), Matter 유체 표면 = 재구성 메시로 같은 경로. 수변 열의 물 행 0.48 ms.

빠진 것: **(a) 화면 공간 굴절의 정확 조건과 실패 픽셀의 처리**, **(b) 수중 카메라**(매질 = 물, 아래에서 본 수면: 전반사·스넬 창, 위 세계의 굴절 뷰), **(c) 코스틱과 수중 광선 기둥**(파도면을 지난 태양광의 집속), **(d) 물 매질의 다중 산란**, **(e) 수면 교차 프레임**(카메라 절반 잠김), **(f) 표면 상호작용**(물결·항적)과 거품, **(g) 강(흐름장)·해안선**(13.1; 사용자 게임 우선순위는 낮음 — 모델만 정의).

### 1.2 정보량

- 수면 = 높이장 h(x, y, t)(FFT 3 캐스케이드 + 국소 물결 텍스처)와 그 법선·야코비안. 화면에서 수면 픽셀 P_w(수변 4K 1.66 M = 20 %).
- 굴절 = 수면 픽셀마다 투과 방향 ω_t(스넬)와 그 광선이 닿는 수중 점의 복사휘도 × 경로 흡수 exp(−σ_a d) — 정보는 "수중 장면을 굴절 방향에서 본 것". 위에서 볼 때 수중 장면의 대부분은 vis buffer에 이미 있다(같은 프레임에 그려짐).
- 수중 카메라 = 매질이 물인 프록셀(흡수 σ_a(λ) 3채널, 산란 σ_s, 위상 g ≈ 0.9), 수면을 아래에서: 스넬 창(θ < 48.6°) 안은 위 세계의 굴절, 밖은 전반사(= 수중 장면의 거울상).
- 코스틱 = 파도면을 지난 태양 광선의 밀도장 C(x, z): 표면 텍셀마다 굴절 방향이 정해지고 깊이 z에서 어디에 모이는지 — 정보량은 캐스케이드 0의 텍셀 수(262 k)와 깊이 슬라이스 수다. 실제 코스틱의 미세 구조(mm)는 **시뮬레이션 표면의 대역(캐스케이드 0 텍셀 2~4 cm)에 없으므로** 정의상 존재하지 않는다: 시뮬레이션 표면에 대해 정확하면 된다.
- 다중 산란 = 물 매질 안 J_w(깊이, μ, μs): 대기의 J_ms와 같은 종류지만 기하가 반평면(수면 경계 + 바닥 알베도)이다.

### 1.3 설계

**(a) 위에서 본 굴절 — 화면 공간 + 유효성 검사 + 광선 fallback.** 수면 픽셀 p: 굴절 방향 ω_t로 수중 표적점 q = p_surface + ω_t × s(s는 vis buffer의 수중 깊이를 따라 1~3회 반복으로 구함). **유효 조건**: q의 화면 투영이 프레임 안이고, 그 위치의 vis buffer 표본이 수중 표면이며(깊이가 수면 뒤이고 q와의 깊이차 ≤ 1 px footprint), 그 사이에 수면 픽셀이 아닌 가림이 없다(광선 구간의 깊이 비교 3점). 유효하면 화면 공간 값이 **정확**(같은 프레임의 vis buffer가 수중 장면의 정확한 가시성이므로). 실패(프레임 밖, 위 세계 물체에 가림, 깊이 불연속)하면 **R의 M 경로 광선 1개**(1.68 ns/광선 [실측 근거 2.6])로 대체한다 — 광선은 수중 hit에서 같은 셰이딩 경로. 비용 = P_w × (탐색 3탭 × 8 B + 유효성) + P_w × f_fail × 1.68 ns = 수변 1.66 M × 0.05 + 1.66 M × f_fail(호수 뷰 [예상] 5~15 %) × 1.68 = **0.08 + 0.14~0.42 ms [예상]** — 지금 물 행 0.48 안의 굴절 몫(≈ 0.1)에 f_fail 항이 더해진다. 흡수는 경로 길이 d의 exp(−σ_a d) 해석(3채널). 파도면 굴절은 픽셀 법선으로 ω_t를 구하므로 정확(시차 조건 불필요: 굴절은 뷰가 아니라 방향).

**(b) 수중 카메라.** 픽셀 매질 분류: 카메라 광선의 시작점이 수면 아래인 픽셀(근평면과 수면 높이장의 교차; (e)) → 그 픽셀은 프록셀이 물 매질을 걷는다(S 프록셀 볼륨의 셀마다 매질 = 수면 높이장 1탭으로 위/아래 판정; 셀이 수면에 걸치면 높이로 분할). 수면을 아래에서 보는 픽셀: 픽셀 법선(뒤집힘)과 시선각 θ_i로 프레넬 R(θ_i)·T(θ_i) (n = 1.33 → 1/n, θ_i > 48.6°는 R = 1). **반사 몫** = 수중 장면의 거울상 → 위에서와 같은 규칙(기울기 < 2°면 평면 반사 카메라 래스터, 파도면 G/M 광선). **투과 몫(스넬 창)** = 위 세계를 굴절 방향에서 본 것: 위 세계는 이 프레임의 vis buffer에 없으므로 화면 공간이 없다 → **굴절 카메라 래스터**: 평면 반사 카메라(2.6)와 같은 기하 경로로, 수면 위 가상 시점에서 창 안 투과 방향 집합(반구 전체가 97° 원뿔로 압축됨)을 덮는 뷰를 래스터한다. 투과 방향의 집합은 반구(180°)라 선형 투영 하나로 못 덮는다 → **큐브 면 2~3개**(위 + 시선 쪽 옆면, 각 해상도 = 화면 각해상도 64 px/° × 압축비 ≤ 1.9 → 면당 ≤ 2048²) 또는 창이 화면 일부(A_window)면 그 방향 원뿔만 덮는 한 면. 비용 = C_planar 식: A_window × P × 0.30 ns + 컬링 0.05 → 창이 화면 40 %(위를 봄) **≈ 1.0 ms [예상]**, 파도면은 법선 섭동 조회(시차 조건 a × 1871 / d < 1 px — 위 세계는 멀어 대개 성립; 아니면 창 픽셀만 R 광선 1.68 ns). 물속에서 위 세계의 광원(태양)은 프록셀의 태양항으로(아래 (c)).

**(c) 코스틱·광선 기둥.** 태양 방향 ω_s, 캐스케이드 0 표면 텍셀(262 k)마다 굴절 방향 ω_t(픽셀 법선)와 텍셀 면적 A_t → 깊이 슬라이스 z_k(0.5 / 1.5 / 4 / 12 m, 로그 간격 4개)의 태양 광공간 코스틱 맵 C_k(1024², 물 영역의 태양 투영 격자)에 **정방향 산포**(텍셀 → 도착점, 면적 가중 원자 add; 접힘(fold)에서 여러 텍셀이 한 점에 겹치는 것을 그대로 셈 = 정확) → 정규화(잔잔한 면이면 1). 비용 = 4 × 262 k 원자 add × 0.019 ns(결맞음 원자 [실측 c_atomic]) + 맵 정규화 4 × 1 M × 4 B = **0.02 + 0.03 ≈ 0.05 ms [예상]**, 물이 보이고 수중 receiver가 있을 때만. 조회: 수중 receiver(바닥·물체 픽셀, 수중 fragment)와 물 매질 프록셀의 태양항에 C(x, z)를 곱한다(태양 광공간 투영 1탭 + 깊이 슬라이스 로그 보간 = 2탭 × 4 B; VSM 조회와 같은 급 0.004 ns/탭) → 수중 픽셀 ≤ 8.3 M × 0.008 = ≤ 0.07, 프록셀 셀 ≤ 1 M × 0.008 = 0.01. **광선 기둥** = 프록셀 in-scatter의 태양항 × C × 수면 투과율 T(θ_s) × exp(−σ_t d) — 별도 패스 없음. 정확 조건: 기하광학, 단일 굴절(수면 1회), 시뮬레이션 표면(캐스케이드 0 대역)에 대해 정확; 수면 아래 물체가 태양광을 가리는 것은 VSM(수중 캐스터도 클립맵 캐스터)이 정확히 처리(코스틱 × VSM 가시성).

**(d) 물 매질의 다중 산란.** 단일 산란은 프록셀(S) 그대로(매질 파라미터만 물). 탁한 물(σ_s d ≥ 1)은 다중 산란이 크므로 **반평면 다중 산란 표 J_w(깊이 32, μ 64, μs 32, 매질별)** — S의 J_ms 빌더(2.3)를 반평면 기하(수면 경계의 프레넬 투과·반사, 바닥 알베도 항 = E_ind와 같은 방식)로 돌린다. 크기 65 k 텍셀 × RGBA16 = 0.5 MB/매질, 재구축 = 물 매질이 정적이라 로드 때 1회(≤ 1 s, 33 ms 요구는 날씨 궤적에만). 조회: 프록셀 셀당 1탭 추가(3채널) ≤ 0.01 ms. 정확 조건: 수평 균질 매질, 평평한 경계(파도의 다중 산란 변화는 캐스케이드 0 파장 ≪ 평균 자유 행로면 무시 가능 — 조건식: λ_wave / (1/σ_t) < 0.1), 바닥 알베도 상수; ε는 J_ms와 같은 게이트(축 2배 수렴 ≤ 0.3 %, C 경로추적기 대조).

**(e) 수면 교차 프레임(카메라 절반 잠김).** 근평면 사각형과 수면 높이장의 교차선이 화면을 둘로 나눈다: 위 픽셀 = 공기 매질 + (a), 아래 픽셀 = 물 매질 + (b). 분류는 픽셀당 높이장 1탭(캐스케이드 0 + 물결) = 0.004 ns × 8.3 M = 0.03 ms(수면 근처에서만, 카메라 높이 |h_cam − h_surface| < 근평면 반높이일 때). 경계 픽셀(교차선이 지나는 1 px 띠)은 coverage 층의 부표본 마스크로 두 매질의 면적 가중(정확 면적 규칙과 같음). 렌즈 위 물방울·젖음은 카메라 저작(4절 물리 카메라의 렌즈 오염 항, 뒤에).

**(f) 표면 상호작용·거품.** 국소 물결 텍스처 W(512², 플레이어 주변 25 m, 5 cm): 2D 파동 방정식(감쇠) 1스텝/프레임 = 262 k 셀 × 5탭 = 0.01 ms [예상, 2.14 시뮬 슬라이스]; 원천 = 물리 접촉(물체 진입·이동, 플레이어 걸음, 파편 낙하: 물리가 접촉점·운동량을 프레임당 목록으로 줌 ≤ 1,024개)과 항적(이동 물체의 궤적을 원천으로). 변위 = FFT + W, 법선도 합. **거품**: 캐스케이드 야코비안 det J < 0.3인 텍셀(부서지는 마루) + 물결 진폭 임계 + 해안 깊이 < 0.3 m → 거품 밀도 텍스처 F(감쇠 이류) → 수면 재질의 알베도·거칠기 층(M 재질 레이어). 물보라 입자는 FX(원천 = 같은 F 임계). 비용 0.02 + 재질 층 1탭.

**(g) 강·해안선(모델 정의만; 사용자 게임 우선순위 낮음).** 강 = 흐름장 v(x) 텍스처(저작·World)로 W와 FFT 노멀 UV를 이류하는 2상 블렌드(표준 flow map) — **저작 외관 모델**이지 시뮬레이션이 아니므로 물리 기준(C)이 없다: 게이트는 "모델 자체와 동일"(결정론·시간 연속성)로 둔다. 해안선 = 깊이에 따른 파고 감쇠와 (f)의 거품; 부서지는 파도는 FFT가 못 만들므로 13.1의 뒤 항목(파도 메시 애니메이션 또는 Matter 유체)으로 남긴다.

### 1.6 최악 dispatch 시간 조건

굴절 fallback 광선·창 광선은 픽셀당 1개(R 파이프라인의 상수 일); 코스틱 산포는 텍셀당 1 원자(262 k × 4 상수); 물결 W는 512² 상수; 굴절 카메라 래스터는 평면 반사 뷰와 같은 구조(면당 컬링·래스터 상수). 데이터 의존 루프 없음.

### 1.7 소유 트랙과 게이트

- **FX(소유 정리, 조율 11:35: 물 = FFT·굴절·흡수·반사 경로 전환·R과의 경계)**: 물 표면 패스 — 수면 메시 변위(FFT + W), 굴절 탐색·유효성·실패 목록, 흡수 적분, 반사 경로 선택(평면 뷰 요청 / G·M 광선 요청), 거품 F, 유체 표면(0.B)과 같은 패스.
- **M**: **유전체(물) 재질 클래스 정의**(프레넬 n = 1.33, 굴절·흡수·코스틱 곱 셰이딩 함수) — 물 표면·유체 표면 패스가 같은 함수를 부른다; 수중 receiver 셰이딩의 코스틱 곱.
- **V**: 수중 픽셀 분류(높이장 탭)와 경계 마스크, 굴절 카메라 뷰의 컬링(평면 반사 뷰와 같은 API).
- **S**: 프록셀 매질 = 물(셀 분할), 코스틱 맵 산포·정규화·조회 함수 `waterCausticAt(worldPos, depth)`, J_w 반평면 표(J_ms 빌더 재사용), 태양항 곱.
- **R**: 굴절 fallback 광선(M 경로 확장: 굴절 방향 원점 = 수면), 굴절 카메라 뷰(평면 반사 뷰 기계의 큐브 면 확장), 수면 아래 반사 규칙.
- **물리·World**: 물결 원천 목록(접촉점·운동량 ≤ 1,024/프레임), 물 볼륨 정의(수면 높이 기준·매질 파라미터·바닥 알베도), 흐름장 저작.
- **FX**: 물보라 입자 원천(거품 임계).
- **C**: 기준 경로추적기에 유전체 경계 + 균질 참여 매질(흡수·산란·위상 g) + 같은 FFT 표면 → 코스틱·수중·굴절 게이트 장면 3개(호수 위 45°, 수중 위 보기(창), 수면 교차).
- 게이트 장면: 게임 벤치의 "물" 케이스(호수 진입 → 잠수 → 위 보기 → 나오기, 300프레임) + 수변 게이트(위에서).

## 2. 파괴 렌더 — 단면 재질, 파편 인스턴싱 (물리 설계 9.1 제안 2026-09-26 11:30에 대한 판정)

### 2.1 물리 제안과 판정

| 물리 제안 | 판정 |
|---|---|
| 사전 저작 패턴: 조각 메시(외피 + 단면)를 자산으로 굽고, 실행 중 새 기하 없음 → 조각 = 인스턴스, 변환은 World Transform 행 | **채택.** 결합 상태의 벽은 **병합 메시(외피만, 클러스터 DAG + 정적 BLAS)**로 그리고, 파괴 사건 tick에 조각 인스턴스 N개로 전환(같은 프레임). 정확 조건 = 조각 외피의 합집합이 병합 메시 표면과 삼각형 단위로 같다(굽기 보장 — 단면은 결합 상태에서 안쪽이라 보이지 않음). 전환 비용 = 인스턴스 N개의 컬링·래스터(N ≤ 수백, 삼각형 합 = 벽과 같음) + 광선용 사건 BLAS(아래) |
| 조각별 BLAS를 자산 시점에 굽기 | **불채택 → 사건 BLAS로 대체.** 조각은 사건 뒤 독립적으로 움직이므로 조각별 BLAS + 인스턴스 F개가 정직한 표현이지만, 작은 BLAS F개의 TLAS 인스턴스와 빌드 고정비가 F에 비례한다. 대신 **사건마다 변형 BLAS 하나**(그 사건의 모든 조각 삼각형을 월드 공간으로 refit; 삼각형이 강체로만 움직이므로 refit이 정확)를 매 프레임 refit — 캐릭터 스킨 BLAS와 같은 경로(R 실측: 캐릭터 256 refit 0.10 ms). 조각이 잠들면(물리 sleep) 정적 병합 BLAS로 이관. 사전 저작·CARVE 둘 다 같은 방식 |
| 실행 중 CARVE: `np_destruction_surface`(NP_DestructionTriangle{a,b,c,feature,material,cut_face})로 렌더가 파편 메시 생성; 외피는 원 자산 재질·UV(feature → 원 면), 단면은 `cut_material` 삼면 투영 | **채택.** 렌더 컴퓨트가 사건 프레임에 정점·재질 버퍼를 만들고(삼각형 ≤ 64 k/사건, 0.02 ms) V의 **런타임 단일 클러스터 메시 풀**에 넣는다(조각 ≤ 64 정점 = 클러스터 하나; 새 V 인터페이스, 0.B 유체 메시와 공유). 단면 재질은 M의 **cut 재질 클래스**(삼면 투영 3탭 블렌드 + 가장자리 손상 층; 픽셀당 +3탭) |
| 조각별 소형 BLAS를 같은 프레임에 빌드, 못 끝내면 이전 통짜 BLAS + 파편 변환으로 한 프레임 | **사건 BLAS로 대체되어 해당 없음.** 사건 프레임: 사건 BLAS **빌드**(refit 아님; 삼각형 ≤ 64 k → [예상] 0.05~0.1 ms, R 실측으로 대체) — 같은 프레임 안에 끝난다(최악 dispatch: 삼각형 상한 64 k/사건, 활성 사건 ≤ 10). 빌드가 프레임 예산을 넘는 경우는 없어야 하며(상한으로 보장) "이전 BLAS로 한 프레임" 규칙은 두지 않는다 |
| 파편 표현 규칙: 투영 크기 p = 2160 r/d ≥ p_min(8 px)이면 강체 파편(인스턴스), 아니면 VFX 파편 입자 | **동의, 렌더 쪽 보충.** 렌더는 두 경로 모두 같은 기하 분류를 거친다: 인스턴스·메시 입자 모두 V 컬링에서 대역 A(폭 ≥ 1.5 px) 또는 대역 B(얇은 조각 실루엣)로 간다. p_min 8 px는 물리 표현 경계이고 렌더 품질 정의는 바뀌지 않는다(8 px 조각의 실루엣은 E 인구조사, 1.5 px 이하는 coverage). VFX 파편 입자는 0.A의 **메시 입자**(GPU 인스턴스 목록) |
| 인스턴스의 메시 id가 tick 중에 바뀌는 사건(통짜 → 조각들, World 행 생성·삭제)을 렌더 그래프가 같은 프레임에 받는가 | **요구로 명시(core·I 확인 요청):** 렌더 인스턴스 목록은 그 프레임이 소비하는 tick의 **커밋된 World 행**에서 만든다(URC_TickSchedule의 (f) 제출 경로). 사건 tick의 행 생성·삭제·메시 id 변경은 그 tick 커밋에 포함되므로 같은 프레임에 보인다 — 조건: 렌더러가 행 스냅샷을 프레임 시작에 한 번 읽고(부분 갱신 없음), 메시 id 변경은 "삭제 + 생성"으로 표현(identity 규칙 3.x: 재구성 이력의 identity는 새 행이라 새로 시작 = 정확) |

### 2.4 소유

물리(파괴 사건·조각 행·`np_destruction_surface`·p_min 규칙), V(런타임 단일 클러스터 메시 풀, 인스턴스 스냅샷), R(사건 BLAS 빌드·refit, GI revision 무효화), M(cut 재질 클래스), FX(파편 입자·먼지), core·I(World 행 커밋 → 인스턴스 목록 같은 프레임 확인), C(파괴 게이트 장면: 벽 파괴 + 방 조명).
