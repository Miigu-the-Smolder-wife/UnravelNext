## 0. 입자 렌더 패스와 유체 표현 (조율 확인 2026-09-26 11:25: UnravelNext에는 입자 렌더 패스가 아직 없다 — 시뮬레이션만 있다)

### 0.A 입자 렌더 패스 (소유 FX; 셰이딩 함수·합성 계약은 M)

**입력(요청 `20260925_FX_particle_render_rules.md` 그대로):** tick 패리티 상태 쌍(posAge·velocity) + 행 표, 렌더 프레임 시각 w의 보간(계속 산 입자 Hermite, 출생·사망 tick 선형), identity = (행, 출생 번호), 크기·색·알파·회전·uv·flipbook은 (프로그램, 이미터 매개변수, 나이)의 순수 함수로 렌더 시각에 평가, 볼륨 입자는 프록셀이 직접 tent-mass 평가(3b). 레코드 종류 4: **스프라이트**(빌보드·축 정렬 사각형, 텍스처·flipbook), **메시**(인스턴스 메시: 탄피·큰 파편), **리본**(궤적: 행마다 K ≤ 8점의 위치 이력 링을 FX 시뮬레이션이 출력 — 새 요구), **볼륨**(3b 레코드).

**정보량.** 픽셀마다 그 픽셀을 덮는 입자들의 깊이 순서와 각 입자의 (알파, 색, 조명). 매끄러운 매질 입자(연기·먼지·안개)는 대역이 낮아 1/4 해상도(4×4 블록)에서 정확하고, 불투명 경계 입자(불꽃 가장자리, 파편, 스파크)는 경계 픽셀만 전해상도 정보다(2.9의 기존 정의).

**단계(프레임마다, 전부 상수 그룹 일):**
1. **빈닝**: 보간 위치·크기로 화면 타일(8×8 셰이딩 타일; 프록셀 타일과 1:1이면 3b와 공유) 목록에 append(타일 항목 E = 입자 × 덮는 타일 수 ≈ 1~2 M @ RPP 622 k; 게임 벤치 ≤ 100 k live → ≤ 0.3 M). 타일 목록 상한(4 k)과 오버플로 비트.
2. **타일 정렬**(14.8 결정 1): groupshared에서 뷰 깊이(입자 중심) 정렬, 0.005 ns/항목 [DesignBench 정렬 단가].
3. **입자 조명(입자당 1회, 픽셀당이 아님)**: 태양 = S의 `shadowSunVisibilityInAir(srvs, worldPos, footprint = max(입자 반경, 픽셀 footprint), out resident)`(S 12:40: receiver 평면 없음, 텍셀 ≤ footprint인 단 선택 + 그 텍셀 규모의 SMRT 원판 필터, 상주 공기 페이지 탐색 ≤ 3단) — 정확 조건: 입자 원판 전체의 평균이 필요할 때(그림자 경계가 입자를 가로지름)는 텍셀 규모 필터가 그 평균이 아니므로 **입자 게이트(FX 참조 커널, 입자 크기 대비 오차 표)가 한도를 넘으면 S가 원판 평균(반경보다 넓은 탭)을 비용식과 함께 추가**한다 + 타일 프로브 블록의 조도(12.3 groupshared, 입자 위치의 SH 평가) + 국소광 ≤ 8(12.4 닫힌 식, 구광원으로 입자 반경 포함) + 프록셀 투과율·in-scatter(입자 깊이에서 1탭 = 3b의 역방향 사용) → 입자당 ≈ 12탭 × 0.004~0.01 ns ≈ 0.1 ns → 622 k × 0.1 = **0.06 ms**. 정확 조건: 조명이 입자 한 개 안에서 매끄러움(매끄러운 매질의 정의); 법선 맵 스프라이트(파편 조각)는 픽셀당 N·L을 텍셀 법선으로 재평가(조도는 입자당 SH 그대로 = 정확).
4. **1/4 해상도 층 채우기**: 타일마다 정렬 목록을 앞→뒤로 알파 합성(premultiplied), 1/4 해상도 픽셀당 (색, 알파, 앞 깊이, 뒤 깊이) 기록. 채움 = Σ 스프라이트 면적/16: RPP 134 M/16 = 8.4 M 표본 × (텍스처 1탭 + 블렌드) 0.005 ns ≈ **0.04 ms**(2.9의 0.03과 같은 급).
5. **전해상도 재평가 픽셀** = (a) 층의 깊이 불연속 픽셀(2.9: 불투명 기하 깊이와 입자 층 깊이 범위가 교차하는 픽셀 → 픽셀마다 정확한 깊이 시험), (b) 불투명 경계 입자의 가장자리 픽셀(알파 1 → 0 경계, 텍스처 알파 마스크의 1/16 인구조사와 같은 E 규칙), (c) **coverage 층 fragment와 깊이가 겹치는 픽셀**(아래 합성 계약). 이 픽셀들은 입자를 **개별 레코드**로 M 합성 목록에 넣는다(16 B: 깊이, premultiplied 색, 알파; 마스크 = 전체). 수 [예상]: (a)+(b) 0.5 M px, (c) P_cov ∩ 입자 깊이 겹침(연기 속 풀: 숲에서 최대 1~2 M) × 겹치는 입자 수 2~4 → 레코드 2~8 M × 0.075 ns(M 합성 층당) = **0.15~0.6 ms**(RPP 상한; 게임 벤치는 풀이 없어 (a)(b)만 ≈ 0.05).
6. **합성 계약(M coverage 합성 4.5와의 관계)**: 픽셀의 최종 순서 = 불투명 → [coverage fragment ↔ 입자 레코드 깊이 순 병합] → 하늘. 1/4 층은 픽셀마다 **레코드 1개**(층의 앞 깊이, 누적 색·알파)로 목록에 들어가되, 그 픽셀에 fragment가 층의 [앞, 뒤] 깊이 안에 있으면 5(c)로 개별 레코드로 풀린다 — 따라서 병합 결과는 항상 정확한 깊이 순서다. fragment가 없는 픽셀(대부분)은 층을 불투명 위에 알파 합성하는 1탭(0.005 ns × 8.3 M = 0.04). 매끄러운 매질 입자는 프록셀에 누적되므로(3b) 모든 레코드가 자기 깊이의 프록셀 투과율을 곱해 자동으로 끼워진다(프록셀 슬라이스 해상도 안에서 정확).
7. **발광 입자의 광원 기여**: 이미터 단위로 합산한 방출(색·세기, 프레임마다 깜빡임 값)을 **구 광원 하나**로 국소광 목록에 넣는다(총구 섬광·불꽃: 그림자 있는 국소광 예산 안 — 매 프레임 전부 다시 그리기 기준이라 1프레임 광원도 같은 단가; 게임 벤치 광원 수십 이하). 반사·GI 안의 발광 형상: 평면 반사 뷰는 입자 패스를 같이 돌리므로 정확(A_r 비용 안); 광선 반사(G/M)는 입자를 보지 못한다 → **발광·큰 입자 시스템(캠프파이어·폭발, ≤ 4 k 입자/시스템)만 절차 AABB BLAS**(6.7의 집합체 TLAS와 같은 종류, 매 프레임 refit 0.01 ms)로 광선이 보게 하고 any-hit에서 알파 합성(광선당 any-hit ≤ 8 상한) — 그 밖의 입자는 광선에 없음을 3절 품질 표에 조건으로 적는다(광원 기여는 7의 구 광원으로 정확).
8. **굴절(열 아지랑이)**: 아지랑이 입자는 1/4 해상도 편향 벡터장 D(px)에 굴절률 기울기 기여를 누적(작은 각 근사에서 선형 합 = 정확 조건 |D| < 8 px)하고, 합성 때 그 입자 깊이보다 뒤의 배경 조회를 D만큼 옮긴다(앞 불투명 기하는 깊이 시험으로 제외). 비용 누적 0.01 + 합성 1탭 0.02.

**비용식 합계 [예상]:** 게임 벤치(≤ 100 k live, 광원 수십): 빈닝·정렬 0.01 + 조명 0.01 + 층 0.02 + 재평가 0.05 + 합성 0.04 + 발광 광원(국소광 행) + 굴절 0.03 ≈ **0.15 ms**; RPP 수변(622 k): 0.02 + 0.06 + 0.04 + 0.15~0.6 + 0.04 + 0.03 ≈ **0.35~0.8 ms** — 2.13 수변 행 0.32는 (c) 겹침 항이 없던 값이라 [예상] 상한이 0.5 오른다(기능 우선 결정에 따라 실측 뒤 예산 단계에서 다룸; 후보 = 겹침 픽셀에서 입자 레코드를 4×4 블록당 1개로 묶는 규칙의 정확 조건 = 블록 안 fragment 깊이가 모두 층 앞 또는 뒤).

**품질 정의·정확 조건(3절 표 갱신):** 깊이 순서 픽셀 정확(타일 정렬 + 병합); 매끄러운 매질 = 프록셀 대역 안 정확(기존 행); 스프라이트 조명 입자당 1회(조건: 입자 안 매끄러움); 경계·겹침 픽셀 = 개별 레코드 정확; 광선 반사는 지정 시스템만 봄(조건 기록); 열 아지랑이 |D| < 8 px. 게이트: C 경로추적기는 입자를 (구/사각 알파 카드 + 매질) 기하로 받아 같은 프레임 시각의 보간 상태를 렌더(C 도구 요청: 입자 상태 덤프 읽기).

**최악 dispatch:** 타일 목록 4 k 상한 + 오버플로 비트, 타일 그룹 상수, 재평가 레코드는 M 합성의 용량 C 안(초과 = OVERFLOW_COVERAGE).

### 0.B 유체 표현 (물리 Matter MPM → FX 표면 재구성 → 물 셰이딩 경로; 물리 설계 세션과 합의 대상)

- **경계(물리 9.2 합의 12:20)**: 물리(2.14, 수변 250 k)는 committed tick n−1·n의 MPM 입자 위치·속도·재질 id를 GPU 버퍼 상태 쌍(`NW_COMPONENT_GPU_BUFFER_REF` 행·링 2벌, soft와 같은 형식)으로 내놓는다. MPM 정렬(k_sort = 4 스텝)이 입자 순서를 바꾸므로 레코드에 **안정 id(u32)**를 두고 정렬은 tick 경계에서만(2 tick마다), 정렬 tick의 버퍼 n에 `prev_slot[i]`(u32, 비정렬 tick은 항등)를 같이 낸다(+4 B/입자): 입자별 보간은 위치_{n−1} = buf_{n−1}[prev_slot[i]]; 표면 재구성만 쓰면 대응이 필요 없다. 슬라이스된 substep 중간 상태는 커밋되지 않는다(렌더는 커밋 버퍼만). **FX**가 렌더 프레임 시각으로 보간해 표면을 재구성하고 그 표면을 **물 표면 패스와 같은 셰이딩 경로**(1절: M 유전체 재질 클래스 — 프레넬·굴절 탐색·흡수·코스틱 곱)로 그린다. 유체 안 매질(mediumMask, 프록셀 매질 = 유체)도 1절 (b)와 같은 규칙(유체 표면 메시가 닫혀 있을 때).
- **재구성**: 희소 격자(셀 = 입자 간격 h, 활성 셀 ≈ 입자/8 × 할로) 밀도 splat(입자당 27셀) → marching cubes(활성 셀만, 삼각형 ≤ 4/셀) → 정점·법선 버퍼(프레임 임시) → V의 런타임 단일 클러스터 메시(2절과 같은 경로)로 래스터. 비용 [예상] 250 k × 27 × 0.019 ns(원자) 0.13 + MC 100 k 셀 × 0.05 ns 0.005 + 래스터 200 k 삼각형 0.02 ≈ **0.15 ms**(수변). 정확 조건: 표면 = 밀도 등위면(입자 반경 r_p = 1.5 h) — MPM의 표면 정의 자체이므로 시뮬레이션에 대해 정확; 물방울 크기 < h인 비말은 표면이 아니라 **스프라이트 입자**(FX가 고립 입자를 0.A 스프라이트로 돌림).
- **광선**: 유체 표면은 프레임마다 바뀌는 메시라 BLAS를 매 프레임 빌드(200 k 삼각형 ≈ 0.1 ms [예상, R 실측으로 대체]) — 반사·굴절 fallback 광선이 필요할 때만(1절 규칙).
- **품질 정의**: 1.5의 물 행 그대로(같은 경로) + "재구성 등위면 = 시뮬레이션 표면 정의". 게이트: 게임 벤치 "유체" 케이스(양동이 쏟기 → 웅덩이, 300프레임) + C 경로추적기(재구성 메시를 유전체로).
- **소유**: 물리(상태 쌍·재질), FX(재구성·패스), M(재질 클래스), V(런타임 메시), R(BLAS 빌드), C(게이트).

## 1. 물 표면·수중

### 1.1 이미 있는 것과 빠진 것

있는 것(ARCHITECTURE 2.6·2.9·2.14): FFT 3 캐스케이드 512²(렌더 프레임 속도, 0.05 ms), 변위는 메시 셰이더, 표면 픽셀의 굴절(화면 공간 + 깊이차 흡수 해석 적분)과 반사(잔잔하면 평면 반사 카메라 래스터, 파도면 G/M 광선; 시차 조건 a × 1871 / d_r < 1 px), Matter 유체 표면 = 재구성 메시로 같은 경로. 수변 열의 물 행 0.48 ms.

빠진 것: **(a) 화면 공간 굴절의 정확 조건과 실패 픽셀의 처리**, **(b) 수중 카메라**(매질 = 물, 아래에서 본 수면: 전반사·스넬 창, 위 세계의 굴절 뷰), **(c) 코스틱과 수중 광선 기둥**(파도면을 지난 태양광의 집속), **(d) 물 매질의 다중 산란**, **(e) 수면 교차 프레임**(카메라 절반 잠김), **(f) 표면 상호작용**(물결·항적)과 거품, **(g) 강(흐름장)·해안선**(13.1; 사용자 게임 우선순위는 낮음 — 모델만 정의).

### 1.2 정보량

- 수면 = 높이장 h(x, y, t)(FFT 3 캐스케이드 + 국소 물결 텍스처)와 그 법선·야코비안. 화면에서 수면 픽셀 P_w(수변 4K 1.66 M = 20 %).
- 굴절 = 수면 픽셀마다 투과 방향 ω_t(스넬)와 그 광선이 닿는 수중 점의 복사휘도 × 경로 흡수 exp(−σ_a d) — 정보는 "수중 장면을 굴절 방향에서 본 것". 위에서 볼 때 수중 장면의 대부분은 vis buffer에 이미 있다(같은 프레임에 그려짐).
- 수중 카메라 = 매질이 물인 프록셀(흡수 σ_a(λ) 3채널, 산란 σ_s, 위상 g ≈ 0.9), 수면을 아래에서: 스넬 창(θ < 48.6°) 안은 위 세계의 굴절, 밖은 전반사(= 수중 장면의 거울상).
- 코스틱 = 파도면을 지난 태양 광선의 밀도장 C(x, z): 표면 텍셀마다 굴절 방향이 정해지고 깊이 z에서 어디에 모이는지 — 정보량은 캐스케이드 0의 텍셀 수(262 k)와 깊이 슬라이스 수다. 실제 코스틱의 미세 구조(mm)는 **시뮬레이션 표면의 대역(캐스케이드 0 텍셀 2~4 cm)에 없으므로** 정의상 존재하지 않는다: 시뮬레이션 표면에 대해 정확하면 된다.
- 다중 산란 = 물 매질 안 J_w(깊이, μ, μs): 대기의 J_ms와 같은 종류지만 기하가 반평면(수면 경계 + 바닥 알베도)이다.

### 1.3 설계

**(a) 위에서 본 굴절 — 화면 공간 + 유효성 검사 + 광선 fallback.** 수면 픽셀 p: 굴절 방향 ω_t로 수중 표적점 q = p_surface + ω_t × s(s는 vis buffer의 수중 깊이를 따라 1~3회 반복으로 구함). **유효 조건**: q의 화면 투영이 프레임 안이고, 그 위치의 vis buffer 표본이 수중 표면이며(깊이가 수면 뒤이고 q와의 깊이차 ≤ 1 px footprint), 그 사이에 수면 픽셀이 아닌 가림이 없다(광선 구간의 깊이 비교 3점). 유효하면 화면 공간 값이 **정확**(같은 프레임의 vis buffer가 수중 장면의 정확한 가시성이므로). 실패(프레임 밖, 위 세계 물체에 가림, 깊이 불연속)하면 **R의 M 경로 광선 1개**(1.68 ns/광선 [실측 근거 2.6])로 대체한다 — 광선은 수중 hit에서 같은 셰이딩 경로. 비용 = P_w × (탐색 3탭 × 8 B + 유효성) + P_w × f_fail × 1.68 ns = 수변 1.66 M × 0.05 + 1.66 M × f_fail(호수 뷰 [예상] 5~15 %) × 1.68 = **0.08 + 0.14~0.42 ms [예상]** — 지금 물 행 0.48 안의 굴절 몫(≈ 0.1)에 f_fail 항이 더해진다. 흡수는 경로 길이 d의 exp(−σ_a d) 해석(3채널). 파도면 굴절은 픽셀 법선으로 ω_t를 구하므로 정확(시차 조건 불필요: 굴절은 뷰가 아니라 방향).

**(b) 수중 카메라.** 픽셀 매질 분류: 카메라 광선의 시작점이 수면 아래인 픽셀(근평면과 수면 높이장의 교차; (e)) → 그 픽셀은 프록셀이 물 매질을 걷는다(S 프록셀 볼륨의 셀마다 매질 = 수면 높이장 1탭으로 위/아래 판정; 셀이 수면에 걸치면 높이로 분할). 수면을 아래에서 보는 픽셀: 픽셀 법선(뒤집힘)과 시선각 θ_i로 프레넬 R(θ_i)·T(θ_i) (n = 1.33 → 1/n, θ_i > 48.6°는 R = 1). **반사 몫** = 수중 장면의 거울상 → 위에서와 같은 규칙(기울기 < 2°면 평면 반사 카메라 래스터, 파도면 G/M 광선). **투과 몫(스넬 창)** = 위 세계를 굴절 방향에서 본 것: 위 세계는 이 프레임의 vis buffer에 없으므로 화면 공간이 없다 → **굴절 카메라 래스터**: 평면 반사 카메라(2.6)와 같은 기하 경로로, 수면 위 가상 시점에서 창 안 투과 방향 집합(반구 전체가 97° 원뿔로 압축됨)을 덮는 뷰를 래스터한다. 투과 방향의 집합은 반구(180°)라 선형 투영 하나로 못 덮는다 → **큐브 면 2~3개**(위 + 시선 쪽 옆면, 각 해상도 = 화면 각해상도 64 px/° × 압축비 ≤ 1.9 → 면당 ≤ 2048²) 또는 창이 화면 일부(A_window)면 그 방향 원뿔만 덮는 한 면. 비용 = C_planar 식: A_window × P × 0.30 ns + 컬링 0.05 → 창이 화면 40 %(위를 봄) **≈ 1.0 ms [예상]**, 파도면은 법선 섭동 조회(시차 조건 a × 1871 / d < 1 px — 위 세계는 멀어 대개 성립; 아니면 창 픽셀만 R 광선 1.68 ns). 물속에서 위 세계의 광원(태양)은 프록셀의 태양항으로(아래 (c)).

**(c) 코스틱·광선 기둥.** 태양 방향 ω_s, 캐스케이드 0 표면 텍셀(262 k)마다 굴절 방향 ω_t(픽셀 법선)와 텍셀 면적 A_t → 깊이 슬라이스 z_k(0.5 / 1.5 / 4 / 12 m, 로그 간격 4개)의 태양 광공간 코스틱 맵 C_k(1024², 물 영역의 태양 투영 격자)에 **정방향 산포**(텍셀 → 도착점, 면적 가중 원자 add; 접힘(fold)에서 여러 텍셀이 한 점에 겹치는 것을 그대로 셈 = 정확) → 정규화(잔잔한 면이면 1). 비용 = 4 × 262 k 원자 add × 0.019 ns(결맞음 원자 [실측 c_atomic]) + 맵 정규화 4 × 1 M × 4 B = **0.02 + 0.03 ≈ 0.05 ms [예상]**, 물이 보이고 수중 receiver가 있을 때만. 조회: 수중 receiver(바닥·물체 픽셀, 수중 fragment)와 물 매질 프록셀의 태양항에 C(x, z)를 곱한다(태양 광공간 투영 1탭 + 깊이 슬라이스 로그 보간 = 2탭 × 4 B; VSM 조회와 같은 급 0.004 ns/탭) → 수중 픽셀 ≤ 8.3 M × 0.008 = ≤ 0.07, 프록셀 셀 ≤ 1 M × 0.008 = 0.01. **광선 기둥** = 프록셀 in-scatter의 태양항 × C × 수면 투과율 T(θ_s) × exp(−σ_t d) — 별도 패스 없음. 정확 조건: 기하광학, 단일 굴절(수면 1회), 시뮬레이션 표면(캐스케이드 0 대역)에 대해 정확; 수면 아래 물체가 태양광을 가리는 것은 VSM(수중 캐스터도 클립맵 캐스터)이 정확히 처리(코스틱 × VSM 가시성).

**(d) 물 매질의 다중 산란.** 단일 산란은 프록셀(S) 그대로(매질 파라미터만 물). 탁한 물(σ_s d ≥ 1)은 다중 산란이 크므로 **반평면 다중 산란 표 J_w(깊이 32, μ 64, μs 32, 매질별)** — S의 J_ms 빌더(2.3)를 반평면 기하(수면 경계의 프레넬 투과·반사, 바닥 알베도 항 = E_ind와 같은 방식)로 돌린다. 크기 65 k 텍셀 × RGBA16 = 0.5 MB/매질, 재구축 = 물 매질이 정적이라 로드 때 1회(≤ 1 s, 33 ms 요구는 날씨 궤적에만). 조회: 프록셀 셀당 1탭 추가(3채널) ≤ 0.01 ms. 정확 조건: 수평 균질 매질, 평평한 경계(파도의 다중 산란 변화는 캐스케이드 0 파장 ≪ 평균 자유 행로면 무시 가능 — 조건식: λ_wave / (1/σ_t) < 0.1), 바닥 알베도 상수; ε는 J_ms와 같은 게이트(축 2배 수렴 ≤ 0.3 %, C 경로추적기 대조).

**(e) 수면 교차 프레임(카메라 절반 잠김).** 근평면 사각형과 수면 높이장의 교차선이 화면을 둘로 나눈다: 위 픽셀 = 공기 매질 + (a), 아래 픽셀 = 물 매질 + (b). 분류는 픽셀당 높이장 1탭(캐스케이드 0 + 물결) = 0.004 ns × 8.3 M = 0.03 ms(수면 근처에서만, 카메라 높이 |h_cam − h_surface| < 근평면 반높이일 때). 경계 픽셀(교차선이 지나는 1 px 띠)은 coverage 층의 부표본 마스크로 두 매질의 면적 가중(정확 면적 규칙과 같음). 렌즈 위 물방울·젖음은 카메라 저작(4절 물리 카메라의 렌즈 오염 항, 뒤에).

**(f) 표면 상호작용·거품.** 국소 물결 텍스처 W(512², 플레이어 주변 25 m, 5 cm): 2D 파동 방정식(감쇠) 1스텝/프레임 = 262 k 셀 × 5탭 = 0.01 ms [예상, 2.14 시뮬 슬라이스]; 원천 = 물리 접촉(물체 진입·이동, 플레이어 걸음, 파편 낙하: 물리가 접촉점·운동량을 프레임당 목록으로 줌 ≤ 1,024개)과 항적(이동 물체의 궤적을 원천으로). 변위 = FFT + W, 법선도 합. **거품**: 캐스케이드 야코비안 det J < 0.3인 텍셀(부서지는 마루) + 물결 진폭 임계 + 해안 깊이 < 0.3 m → 거품 밀도 텍스처 F(감쇠 이류) → 수면 재질의 알베도·거칠기 층(M 재질 레이어). 물보라 입자는 FX(원천 = 같은 F 임계). 비용 0.02 + 재질 층 1탭.

**(g) 강·해안선(모델 정의만; 사용자 게임 우선순위 낮음).** 강 = 흐름장 v(x) 텍스처(저작·World)로 W와 FFT 노멀 UV를 이류하는 2상 블렌드(표준 flow map) — **저작 외관 모델**이지 시뮬레이션이 아니므로 물리 기준(C)이 없다: 게이트는 "모델 자체와 동일"(결정론·시간 연속성)로 둔다. 해안선 = 깊이에 따른 파고 감쇠와 (f)의 거품; 부서지는 파도는 FFT가 못 만들므로 13.1의 뒤 항목(파도 메시 애니메이션 또는 Matter 유체)으로 남긴다.

### 1.6 최악 dispatch 시간 조건

굴절 fallback 광선·창 광선은 픽셀당 1개(R 파이프라인의 상수 일); 코스틱 산포는 텍셀당 1 원자(262 k × 4 상수); 물결 W는 512² 상수; 굴절 카메라 래스터는 평면 반사 뷰와 같은 구조(면당 컬링·래스터 상수). 데이터 의존 루프 없음.

### 1.7 소유 트랙과 게이트

- **FX(소유 정리, 조율 11:35: 물 = FFT·굴절·흡수·반사 경로 전환·R과의 경계)**: 물 표면 패스 — 수면 메시 변위(FFT + W), 굴절 탐색·유효성·실패 목록, 흡수 적분, 반사 경로 선택(평면 뷰 요청 / G·M 광선 요청), 거품 F, 유체 표면(0.B)과 같은 패스.
- **M**: **유전체(물) 재질 클래스 정의**(프레넬 n = 1.33, 굴절·흡수·코스틱 곱 셰이딩 함수) — 물 표면·유체 표면 패스가 같은 함수를 부른다; 수중 receiver 셰이딩의 코스틱 곱.
- **V**: 수중 픽셀 분류(높이장 탭)와 경계 마스크, 굴절 카메라 뷰의 컬링(평면 반사 뷰와 같은 API).
- **S**: 프록셀 매질 = 물(셀 분할), 코스틱 맵 산포·정규화·조회 함수 `waterCausticAt(worldPos, depth)`, J_w 반평면 표(J_ms 빌더 재사용), 태양항 곱.
- **R**: 굴절 fallback 광선(M 경로 확장: 굴절 방향 원점 = 수면), 굴절 카메라 뷰(평면 반사 뷰 기계의 큐브 면 확장), 수면 아래 반사 규칙.
- **물리·World**: 물결 원천 목록(접촉점·운동량 ≤ 1,024/프레임), 물 볼륨 정의(수면 높이 기준·매질 파라미터·바닥 알베도), 흐름장 저작.
- **FX**: 물보라 입자 원천(거품 임계).
- **C**: 기준 경로추적기에 유전체 경계 + 균질 참여 매질(흡수·산란·위상 g) + 같은 FFT 표면 → 코스틱·수중·굴절 게이트 장면 3개(호수 위 45°, 수중 위 보기(창), 수면 교차).
- 게이트 장면: 게임 벤치의 "물" 케이스(호수 진입 → 잠수 → 위 보기 → 나오기, 300프레임) + 수변 게이트(위에서).

### 1.8 수면의 정확한 위치 — 월드 클립맵(2차 광선·질의)과 뷰 격자(카메라 화면) (엔진 1 W; 조율 결정 2026-09-26 밤, 재설계 22:30 조율 동의)

**정정(수식과 실측).** 처음 판(9750765, 0967e64)의 주장 세 가지가 틀렸다.
- **층 규칙이 성립하지 않았다.** 카메라 중심 512² 층은 거리 d의 점을 s_ℓ ∈ [d/256, d/128]인 층에 담는다(창 반경 256 s_ℓ, 안쪽 절반은 더 고운 층). 4K 60°(θ = 2.73e-4 rad/px)에서 픽셀 발자국 f = dθ에 대해 **s_ℓ/f = 1/(256θ)…1/(128θ) = 14~29 px**다. "s_ℓ ≤ f/2인 층"은 어디에도 없었다. 그래서 "화면 면 오차 0.05 px" 주장은 틀렸다.
  - 실제 오차는 f~2s_ℓ 사이 대역의 3σ(0.048 λ)와 이중선형 오차 (ks)²/8 A다. 1~2 px로 추정한다[예상]. 품질 정의 0.5 px를 넘는다.
  - 따라서 클립맵은 카메라 화면의 면이 될 수 없다. 카메라 화면은 픽셀 밀도의 뷰 격자(B)가 맡는다.
- **고정점 반복 6회는 수렴하지 않았다.** 미해결 점이 1.2 %였다[실측, RTX 4080, 풍속 10 m/s]. 압축이 강한 곳(‖∂D/∂x₀‖ → 1)에서 6회로는 0.02 s_ℓ에 닿지 않는다. 5×5 접힘 탐색도 간격(R/2 = 2 m)이 cm 크기 접힘 가지보다 훨씬 커서 찾지 못했다. → A의 산포 구성으로 바꿨다.
- **방문 상한 58은 틀렸다.** 스치는 광선이 상한 160에 닿았다(5/4096)[실측]. 층을 바꿀 때 밉을 0부터 다시 올라가는 비용을 빠뜨렸고, 창 경계에서 노드가 창 밖 1칸을 건너뛰는 결함도 있었다(깊이 오차 9.6e-4 t). → A의 정수 순회와 증명된 상한으로 바꿨다.

#### A. 월드 클립맵 — 2차 광선, 기준 경로추적기, 질의, 코스틱 (구현 273b06e)

**역할.** 카메라 밖에서 오는 광선이 쓴다: C 기준 경로추적기, 수중 굴절·반사 광선, 코스틱의 태양 광선, 물리·게임플레이 질의. 해상도 조건은 카메라 픽셀이 아니라 그 광선의 원뿔 폭이다. 카메라 화면은 B가 맡는다.

**표현.** 층 ℓ = 0..L−1, 층마다 512², s_ℓ = s_0 2^ℓ(s_0 = 1.5625 cm), 카메라에 텍셀 단위로 붙는다. 텍셀 = (H, x₀ − w, 표지). 최대·최소 밉은 9단이다. VRAM은 12층에서 50 MB, 산포 키가 25 MB다.

**구성(프레임마다).**
1. **산포(윗면).** 층 ℓ의 휴지 격자(창 + 여유 M_ℓ = ⌈R/s_ℓ⌉ + 1)를 s_ℓ 저역의 D로 변위한다. 휴지 사각형 하나를 삼각형 둘로 나누고, 삼각형이 덮는 격자점마다 (순서 보존 높이 32비트 | 휴지 오프셋 2×16비트)를 64비트 원자 max로 쓴다.
   - 접힌 곳에서는 가장 높은 판이 이긴다. 이것이 윗면 정의이며, 이 메시에 대해 정확하다. 뒤집힌 삼각형도 같은 방식으로 덮는다.
   - 해가 수렴하지 않는 경우가 구조적으로 없다.
2. **다듬기.** 메시의 x₀에서 Newton 2회를 돌린다(야코비안 I + ∂D/∂x₀, 기울기 텍스처에서 읽는다). 잔차가 ≤ 0.02 s_ℓ이고 메시 x₀에서 1.5 s_ℓ 안이면(같은 판) 연속면 값을 쓴다. 아니면 메시 값을 쓴다(접힘 가장자리, 야코비안 → 0).
   - 덮이지 않은 점은 w − D(w)에서 Newton으로 풀고 센다. 이런 점은 변위가 R을 넘거나 삼각형 루프 상한(8×8)을 넘을 때만 생긴다.
3. 최대·최소 밉.

**교점(oceanRefineCounted).** 상태는 정수 셀이고, 노드는 cell >> mip이다.
- 노드의 최대가 그 구간에서 광선의 최저 높이보다 낮으면 출구 면을 건너 이웃으로 간다. 출구 축은 정수 한 칸, 다른 축은 출구점의 셀을 노드 안으로 고정한다. 그 뒤 밉을 한 단 올린다. 아니면 내려간다.
- 셀에서는 이중선형 면과 시선의 2차식 첫 근을 구한다.
- 위치는 층 원점 기준 상대 좌표로 계산한다. 카메라 근처의 뺄셈이 정확하므로 월드 원점에서 멀어도 정밀도가 유지된다.
- 층: 창이 그 점을 담는 가장 고운 층, 또는 광선 원뿔 규칙이 더 거칠면 그 층. 층은 광선을 따라 커지기만 한다.

**방문 상한은 결과를 바꾸지 않는다(증명).**
- 건너뛰기와 빗나간 잎은 모두 셀을 광선 방향으로 한 축 한 칸 이상 옮긴다. 그래서 층마다 최대 511 + 511번이다.
- 내려가기는 올라가기를 되돌리는 것이고, 올라가기는 그 이동 때만 일어난다(시작 밉 8회 추가).
- 층 전환은 최대 L − 1번이다.
- 따라서 방문 ≤ 2 × 1024 × L + 32(L = 12에서 24 608)이고, 이 상한에 닿으면 증명이 깨진 것이다(OCEAN_REFINE_CAP, 게이트에서 0).

**정확 조건(문장).**
- 교점은 "층 ℓ(t)의 이중선형 H와 시선의 첫 교점"과 부동소수 오차 안에서 같다.
- H는 다듬어진 점에서 연속면(층 저역)과 잔차 0.02 s_ℓ 안에서 같고, 접힘 가장자리 점에서는 메시 윗면과 같다(표지 1).
- 해상도는 광선 원뿔에 대한 것이다. 카메라 픽셀에 대해서는 14~29 px 텍셀이다(위 정정).

**요구 하드웨어.**
- SM 6.6(바인드리스).
- 64비트 원자 max: 설명자 힙 자원 위, D3D12_OPTIONS11.AtomicInt64OnDescriptorHeapResourceSupported. 생성 때 검사하고 없으면 명확한 오류를 낸다.
- NVIDIA Turing 이상은 지원한다(개발 PC RTX 4080 확인). AMD RDNA2/3와 Intel Arc에서 이 비트가 켜지는지는 **확인이 필요하다**. 꺼져 있으면 산포를 32비트 2단(높이 max → 오프셋 기록)으로 바꾸는 대안이 필요하고, 그 비용은 원자 1회 추가다[예상].

**게이트 결과 [실측, WARP 정확성; 하드웨어 시간은 사용자 게임 뒤].** 카메라 두 대(바다 위 12 m; 4 m, 원점에서 1.7 km), 광선 4096개씩, CPU 이중정밀 기준(셀 보행 + 부호 분석 + 이분법)과 비교했다.
- 깊이 |Δt|/t ≤ 2.7e-6, 적중/빗나감 불일치 0, 상한 도달 0.
- 방문 수: 중앙값 32, 99 % 82, 최대 145.
- 구성: 다듬어진 점 99.0 % / 99.95 %, 접힘 가장자리 메시 값 1.0 % / 0.05 %, 덮이지 않은 점 0. 무작위 1만 점의 잔차 최대 0.0199 s_ℓ.
- 밉은 CPU 피라미드와 비트 단위로 같다.

**비용 [예상].**
T_A = 산포 Σ_ℓ (512 + 2M_ℓ)² × (3 표본 × 81/64) + 해소 3.1 M × (2 × 6 + 3 표본) + 밉 0.03 ms. 약 18 M + 47 M 표본이므로 0.3~0.5 ms다. 2차 광선이 없는 프레임에서는 만들지 않는다(소비자가 있을 때만 기록).

#### B. 뷰 격자 — 카메라 화면의 정확한 수면 (설계, 구현 전 microbench로 바닥을 잰다)

**목표 면.** S_px = 픽셀 발자국으로 대역 제한한 변위면이다. D를 휴지면 위 픽셀 발자국(비등방: 시선 방향으로 1/sin e배 늘어남)으로 거른다. 구현은 SampleGrad에 이방성 16을 쓴다. 16:1을 넘는 스침(e < 3.6°)에서는 하드웨어가 더 흐리게 거른다. 이는 걸러진 대역이 넓어지는 것이지 형상 오차가 아니다.
- 품질: 그린 면이 S_px와 0.5 px 안에 있다. 목표는 0.15 px[예상, 아래 오차식].

**구조.**
1. **먼 장: 등각 격자.** 카메라의 방위 φ × 앙각 e 격자(월드 위 방향 기준, 간격 θ)로, 화면의 각 창에 여유를 더해 덮는다. 각 격자점의 휴지점 = 그 방향의 시선과 휴지면 y = 수위의 교점이다. 여유는 휴지점 거리 t에서 (R + A_h)/t rad이다(R은 수평, A_h는 수직 변위의 상한). 먼 장은 t ≥ r_n인 휴지점만 담으므로 여유 ≤ (R + A_h)/r_n이다.
2. **가까운 장: 월드 격자.** t < r_n인 휴지점은 카메라 중심의 중첩 월드 격자에 담는다. 등각 격자로는 발 밑 여유가 화면 전체로 커지기 때문이다(수영 시점 H_c → 0).
   - 간격은 가장 고운 대역(λ_min = 6.25 cm, 3σ 진폭 3 mm)의 선형 보간 오차가 0.5 px(0.5 tθ)가 되는 값이다. (ks)²/8 · A ≤ 0.5 tθ에서 s(t) = (λ_min/2π) √(4 tθ / A_min)이다. 1 m에서 6 mm이고 √t로 늘어난다.
   - 층 i는 간격 5 mm·2^i, 반경 4^i m다. 절두체 ⊕ 여유 쐐기로 자르면 r_n = 16 m에서 약 1 M 점이다[예상].
3. **산포(첫 교점).** 두 격자의 변위된 삼각형을 픽셀로 컴퓨트 래스터한다. 픽셀 중심을 덮으면 (시선 깊이 32비트 | 삼각형 id 32비트)를 64비트 원자 min으로 쓴다. 겹치는 띠(폭 ≥ R + A_h)에서는 가까운 쪽이 이긴다. 두 메시의 차이는 각자의 보간 오차 안이다.
4. **해소.** 이긴 삼각형의 무게중심으로 x₀와 깊이를 구한다. 연속면 S_px에 대해 시선을 따라 Newton 2회로 마무리한다(첫 교점 가지 안). 출력은 물 깊이(view depth), x₀(셰이딩은 x₀에서 기울기·거품·물결을 읽는다), 표지다.
   - 이 버퍼가 물 층·가장자리 기록(렌더 A의 coverageSpecial kind 2)의 깊이·법선 출처다.

**오차식.** 격자 간격이 화면 1 px일 때, 남는 오차는 격자 나이퀴스트 근처 대역(λ ≈ 2 px 투영)의 선형 보간 오차다. 3σ = 0.048 λ, 필터 감쇠 후 ≤ 0.1~0.15 px[예상]. 조건: 스펙트럼 꼬리 c_s ≤ 0.016(α ≤ 0.01). 게이트에서 연속면 대비 분포를 잰다.

**비용식.** 부하는 줄이지 않는다.
- V_far = (W + 2m) × (행 수 ≤ 화면 행 + 아래 여유)이다. 4K에서 약 9~10 M이고, 수변(물 픽셀 비율 ρ_w)에서는 휴지면 마스크(수체 안)로 자르므로 ≈ ρ_w × 9 M + 가장자리다.
- V_near ≈ 1 M.
- 표본: (V_far + V_near) × 3 캐스케이드 × a_iso(이방성 평균 비용, 스침 행에서 최대 16) 표본.
- 래스터: 삼각형 2V, 1 px 미만 삼각형의 원자 min ≈ 픽셀 수 × 깊이 복잡도.
- 해소: 물 픽셀 P_w × (Newton 2회 × 6 표본).
- 합 [예상, microbench로 교체]: 화면 전체 물 약 0.8~1.2 ms, 수변(P_w 1.66 M) 약 0.3~0.5 ms. 앞선 A 방식을 화면에 쓸 때의 추정(0.45~0.6 / 0.8~1.1)과 같은 급이다. 그러나 이쪽은 0.5 px 정의를 만족한다.

**microbench(구현 전, 사용자 게임 뒤 하드웨어; 지금은 WARP 정확성만).** 수변과 화면 전체를 따로 적는다.
- (1) 변위 표본 처리량: SampleGrad 이방성 1/4/16, 캐스케이드 3장, 격자 순서 접근.
- (2) 64비트 원자 min 처리량: 1 px 삼각형 분포(화면 순서·무작위), 깊이 복잡도 1~3.
- (3) 1 px 삼각형 처리량: 컴퓨트 래스터(스레드당 사각형 1개, 픽셀 판정 ≤ 64) 대 하드웨어 래스터(메시 셰이더 격자). 빠른 쪽을 고른다.
- 결과로 위 비용식의 계수를 바꾼다.

**최악 dispatch 시간 조건.**
- 산포: 스레드는 사각형 하나(삼각형 둘)를 맡고, 픽셀 판정은 삼각형마다 8×8 이하다(일정한 일).
- 8×8을 넘는 삼각형(가까운 장의 가파른 파면)은 목록에 넣는다. 그 뒤 접두합과 간접 dispatch로 8×8 타일당 스레드 하나를 쓰고, 스레드는 이진 탐색으로 자기 삼각형을 찾는다(일정한 일 + log N).
- dispatch 시간은 Σ 타일 = (덮인 면적 × 깊이 복잡도)/64 + 삼각형 수에 비례한다. 이 비례량을 비용식에 적었고, 병적 장면(수영 시점, 가까운 가파른 파도)으로 게이트에서 잰다.

**게이트(B).**
- (1) 픽셀별 첫 교점을 CPU 이중정밀 삼각형 메시 기준과 비교한다(작은 영상): 깊이 차 ≤ 1e-5 t, 적중/빗나감 불일치 0.
- (2) 연속면 S_px 대비 오차 분포(px): 99.9 % ≤ 0.5 px.
- (3) 수변·화면 전체·수영 시점 시간(하드웨어, 사용자 게임 뒤).
- (4) 카메라 이동 시 시간 연속성(격자가 카메라와 함께 움직이므로 헤엄침이 없는지, 같은 휴지점 표본의 프레임 간 차이로 잰다).
- (5) C 대조: C 기준 경로추적기는 카메라 광선에 대해 같은 S_px(연속면 Newton)를, 2차 광선에 대해 A를 추적한다.

### 2.1 물리 제안과 판정

| 물리 제안 | 판정 |

## 6. 노출·톤맵·HDR 출력 (소유 M; 표시 계약은 core·I)

### 6.1 정보량

프레임의 복사휘도 L(픽셀, cd/m² 단위의 물리량: 태양 1.6e9, 하늘 8e3, 실내 1e2, 밤 1e−2)을 표시 장치의 밝기 범위(SDR 80~250 cd/m², HDR 1,000~4,000 cd/m² 피크)로 사상한다. 정보는 (a) **노출 값** E(장면 밝기 통계의 함수 또는 저작 값), (b) **톤 곡선**(장면 → 표시 밝기의 단조 함수), (c) 표시 장치의 전달 함수·색역·피크(EDID/DXGI HDR 메타데이터). 물리 카메라(4절)에서 노출 = ISO·셔터·조리개의 함수이고 자동 노출은 그 세 값을 장면 통계로 정하는 것이다.

### 6.2 설계

- **장면 밝기 통계(자동 노출 입력)**: 셰이딩 커널이 픽셀 복사휘도의 로그 히스토그램(64구간, 타일 groupshared 집계 → 전역 원자 64개)을 쓴다 — 비용 8.3 M × 1 ALU + 타일당 원자 64 = 0.01 ms. 통계 = 히스토그램의 중심 가중 평균(저작: 중심 가중치 σ, 상·하위 절단 %)과 시간 적응(눈 적응: 밝→어둠 τ_d, 어둠→밝 τ_b 초, 지수 평활 — 결정론: 프레임 Δt로 정확 적분).
- **노출 결정**: 물리 카메라 모드(4절)에서는 ISO·셔터·조리개 저작 값 → EV; 자동 노출은 통계 밝기를 목표 회색(저작, 기본 18 %)에 맞추는 EV_auto = log2(L_avg / (0.18 × K)) (K = 반사광 노출계 상수 12.5)를 저작 범위 [EV_min, EV_max] 안에서 적응 시간으로 따라간다. 게이트·기준 영상은 **고정 노출**(manifest 값)로 비교한다(자동 노출은 시간 함수라 정적 게이트에서 끄고 게임 벤치 "실내→실외" 케이스에서 적응 시간 함수를 결정론으로 검증).
- **톤 곡선**: 기본 = 물리적 필름 곡선이 아니라 **표시 참조 기준의 단조 곡선**(ACES와 같은 sigmoid 계열, 저작 가능한 어깨·발가락 매개변수, 색상 보존형: 휘도에 곡선을 적용하고 채도는 별도 매개변수로 — 3채널 개별 곡선의 색상 왜곡을 피함). 컬러 그레이딩 LUT(3D 33³, 저작)는 곡선 뒤. 정확 조건: 곡선은 표시 사상이지 물리량이 아니므로 "정확"의 대상이 아니다 — 게이트는 **곡선 앞 HDR 복사휘도**에서 비교하고(기준 영상 = 선형 HDR), 곡선·그레이딩은 결정론·단조성만 검증한다.
- **출력 경로**: (i) SDR: sRGB 8/10 bit(RGB10A2 스왑체인, 지금 경로), (ii) **HDR10**(RGB10A2 + PQ, BT.2020, DXGI_COLOR_SPACE_RGB_FULL_G2084_NONE_P2020, HDR 메타데이터 = 표시의 최대·최소 밝기·MaxCLL), (iii) **scRGB**(RGBA16F 선형, BT.709 원색, Windows 자동 톤맵 없음, 스왑체인 8 B/px). 모드는 표시 장치와 설정 층이 정하고 톤 곡선의 피크 = 표시 피크(HDR)에 맞춘다. HDR 모드에서 스왑체인 8 B/px는 2.13b 스왑체인 행 +100 MB(RGBA16F ×3).
- **셰이딩 커널 안 적용**(2.11 그대로: 톤맵을 커널이 하고 최종 4 B/8 B 쓰기): 노출 EV는 프레임 시작에 상수(직전 프레임 통계 + 적응 = 1프레임 지연, 결정론) → 커널이 L × 2^EV → 곡선 → 출력 인코딩(sRGB/PQ/선형). 비용: 픽셀당 ALU ≈ 20 + LUT 1탭(그레이딩 켤 때) ≈ 0.01~0.02 ms(셰이딩 행 안 "톤맵 0.01" 그대로).
- **디더**: 10 bit 출력에 삼각 디더(결정론 해시) — 밴딩 방지, 비용 0.
- **UI·Unity 합성**: Unity UI는 스왑체인 위에 그 색 공간으로 합성(HDR 모드에서 sRGB UI를 PQ/scRGB로 변환하는 것은 I 경계 — 요청 파일).

### 6.3 비용식·품질 정의

| 항 | 값 | 정확·조건 |
|---|---:|---|
| 로그 히스토그램 | 0.01 ms | 결정론(원자 add는 정수 카운트라 순서 무관) |
| 노출 적응 | 0 (CPU 상수) | 지수 평활의 Δt 적분 = 정확; 게이트는 고정 노출 |
| 톤 곡선 + 그레이딩 LUT + 인코딩 | 0.01~0.02 (셰이딩 행 안) | 단조·결정론; 기준 비교는 곡선 앞 HDR |
| HDR 스왑체인 | +100 MB(scRGB) | 표시 메타데이터 = 장치 값 |

**최악 dispatch**: 없음(픽셀 상수 일).

**소유**: M(히스토그램·노출 결정·곡선·그레이딩·인코딩, 품질 키), core·I(스왑체인 색 공간·HDR 메타데이터·Unity UI 합성 경계·설정 층), RPP-1(manifest의 고정 노출·게임 벤치 실내→실외 케이스).

## 7. 디버그 드로우, 버퍼 시각화, 편집기 오버레이 (M0: 편집기 씬 뷰; 소유 core, 경계 I)

### 7.1 정보량과 설계

편집기 씬 뷰는 **렌더 텍스처 카메라**(8절)의 한 인스턴스(편집기 창 크기, 일반 프레임과 같은 경로: 품질 키만 다를 수 있음) + **오버레이 층**이다. 오버레이의 정보는 장면이 아니라 도구다: 기즈모(이동·회전·크기 조작자), 선택 외곽선, 그리드, 디버그 도형(선·점·문자·상자·구·화살표), 물리 디버그(충돌체·접촉·조인트), 내비·오디오 볼륨 등 다른 모듈의 디버그 형상.

- **디버그 도형 API(core)**: CPU·GPU 양쪽에서 append하는 **선분·삼각형·점·문자 버퍼**(프레임 임시, 상한 1 M 선분·256 k 삼각형·64 k 글자; 초과는 통계 비트) — GPU 커널(V·S·M·R·FX·물리)이 자기 데이터를 직접 그릴 수 있게 HLSL `debugLine(a, b, color)`·`debugText(pos, id)` 공개 함수. 드로우는 셰이딩 뒤 별도 패스: 선은 픽셀 폭 지정(1~3 px, 화면 공간 사각형 확장 메시 셰이더), 깊이 시험 옵션(장면 깊이 vs 없음), 알파. 비용 = 선분 수 × 픽셀 길이 × 0.01 ns(ROP) → 100 k 선 × 100 px = 0.1 ms(디버그 켤 때만).
- **선택 외곽선**: 선택된 인스턴스 id 집합 → vis buffer의 id 일치 마스크 → 3×3 팽창 경계(E 검출과 같은 identity 시험) → 색 합성. 비용 = 8.3 M × 2탭 = 0.03 ms.
- **그리드**: 해석 그리드 셰이더(월드 평면, 거리 기반 밉 페이드, 축 색), 깊이 시험, 1 드로우 = 0.02 ms.
- **기즈모**: 디버그 삼각형·선 API로 그리며 깊이 시험 없음 + 항상 위. 피킹(마우스 → 객체·기즈모 축) = vis buffer id 읽기(1 px 되읽기, 1프레임 지연) + 기즈모는 CPU 광선-형상 시험.
- **버퍼 시각화(모든 트랙 공통 도구)**: 품질 키 `debug.view = { visId, depth, hiz, gbufferNormal, albedo, roughness, coverageCount, coverageDepth, bandMask, vsmPages, vsmVisibility, froxelT, probeIrradiance, reflectionPath, particleLayer, exposureHistogram, overdraw, ... }` — 셰이딩 커널이 아니라 **별도 시각화 패스**(선택한 버퍼를 색 사상해 스왑체인에 씀, 톤맵 우회). 비용 0.02 ms(켤 때만). 수치 표시(픽셀 값 텍스트, 마우스 위치 되읽기)는 디버그 문자 API.
- **편집 중 즉시 반영**: 재질·광원·인스턴스 변경은 렌더러의 revision 키(`renderFieldKey` 승계)로 캐시·이력을 무효화 → 다음 프레임에 정확(GI 캐시 수렴 ≤ 8프레임은 2절과 같은 게이트).
- **핫 리로드**: 셰이더·재질 프로그램 파일 변경 → PSO 재컴파일(백그라운드, 완성 뒤 교체; DXIL 한도 규칙), 자산 변경 → 스트리밍 재적재(3단 관리자 경로).

### 7.2 I 경계(요청)

씬 뷰 = Unity EditorWindow 안의 렌더 텍스처(8절 카메라 출력을 Unity 텍스처로 공유: 기존 TitanSRP 브리지의 공유 핸들 경로), 입력(마우스·키)은 Unity가 받아 피킹 요청(픽셀 좌표)을 렌더러에 보내고 id를 되받는다(1프레임 지연 허용). 플레이 모드 = 같은 렌더러의 게임 뷰(스왑체인 또는 Unity 게임 뷰 텍스처). 기즈모·그리드·선택 외곽선은 렌더러 오버레이(Unity의 기즈모 드로우는 쓰지 않음 — 깊이·색 공간 일관성). 두 뷰가 동시에 열리면 렌더 텍스처 카메라 2개(8절 예산: 씬 뷰는 편집기 창 해상도, 프레임 예산은 합산 — 편집기에서는 165 fps 목표가 아니라 상호작용 가능성만: 설정 층).

### 7.3 비용·품질

디버그·오버레이는 게이트 밖(품질 정의 없음; 결정론과 상한만). 켜지 않으면 비용 0(패스 생략). 최악 dispatch: 버퍼 상한으로 상수.

**소유**: core(디버그 API·드로우 패스·시각화 패스·피킹·핫 리로드·revision), I(EditorWindow 텍스처 공유·입력·플레이 모드 전환), M(시각화 색 사상 함수는 각 트랙이 자기 버퍼에 제공), 각 트랙(자기 버퍼의 `debug.view` 항목).

## 8. 렌더 텍스처 카메라 (M0: 편집기 씬 뷰; 게임: 거울·감시 카메라·조준경·포털; 소유 core)

- **정의**: 주 카메라와 같은 프레임 그래프를 다른 뷰 매개변수(위치·투영·해상도·품질 키 부분집합)로 한 번 더 도는 것. 출력 = 텍스처(재질이 읽거나 UI가 씀). 평면 반사 뷰(2.6)·굴절 카메라 뷰(1절)와 같은 기계(`view` 슬롯)의 일반화: 뷰마다 컬링·VSM 요청·프록셀·셰이딩이 돌고, 캐시(GI 월드 캐시·VSM 페이지·브릭·텍스처)는 뷰 사이에 **공유**(같은 세계)한다.
- **정보량·비용**: 뷰 픽셀 P_v × 픽셀당 밴드 파이프라인 단가(2.6의 0.30 ns: 해석·가시성·셰이딩·합성) + 뷰 고정비(컬링 0.05 + VSM 요청 병합 + 프록셀 볼륨 한 벌 21.5 MB) → 1024² 조준경 = 1 M × 0.30 + 0.05 ≈ **0.35 ms**; 512² 감시 카메라 4대 = 4 × (0.26 M × 0.30 + 0.05) ≈ 0.5 ms. 뷰마다 프레임 예산에 합산되므로 게임의 뷰 수·해상도는 저작 예산(설정 층)이다. 편집기 씬 뷰 = 편집기 창 해상도(예: 2560×1440 → 1.1 ms + 오버레이).
- **품질 정의**: 주 뷰와 같은 품질 키면 같은 정확성(같은 경로); 품질 키 부분집합(예: 감시 카메라는 반사 K만, 프록셀 절반 해상도)은 그 뷰의 정의로 게이트. 이력(반사 누적·프로브)은 뷰마다 별도(identity·revision 규칙 동일). 재귀(거울 속 거울)는 깊이 1(뷰가 다른 뷰의 텍스처를 읽을 때 그 텍스처는 직전 프레임 값 = 1프레임 지연을 정의로 둠).
- **VRAM**: 뷰마다 트랜지언트 집합(해상도 비례; 별칭 풀에 합산)과 프록셀 볼륨·이력 텍스처 — 2.13b에 "추가 뷰 × 해상도 비례" 행.
- **최악 dispatch**: 주 뷰와 동일(뷰는 같은 커널).
- **소유**: core(뷰 슬롯 일반화·프레임 그래프·텍스처 출력·예산 설정 층; I의 요청 `20260926_I_multiple_views.md`(뷰 키·뷰별 이력·세계 캐시 공유·장면 갱신 시뮬 프레임당 1회)와 같은 일이라 하나로 합친다), V·S·M·R·FX(뷰 매개변수화는 이미 평면 반사 뷰로 있음 — 확인만), I(Unity 텍스처 공유·재질 바인딩). **M0 뒤**(사용자 결정 12:25: 편집기 씬 뷰는 Unity 기본 미리보기).

## 3. 1인칭 뷰 모델 (M0 포함; COVERAGE 14.12 (1)의 확장)

### 3.1 정의와 정보량

뷰 모델 = 카메라에 붙은 스킨 메시(손·도구, 삼각형 ≤ 100 k, 재질 2~4종, 카메라 0.2~1 m). 화면의 10~25 %를 덮고 픽셀 footprint가 0.1~0.5 mm라 세계의 어떤 표현(VSM 클립맵 단 0 텍셀 8 mm, GI 캐시 간격, 프로브 16 px)보다 곱다. 정보량은 (a) 뷰 모델 자체의 가시성·재질(일반 픽셀과 같음), (b) 뷰 모델 위의 그림자(자기 그림자 + 세계 → 뷰 모델), (c) 뷰 모델이 세계에 미치는 것(그림자·반사·차폐), (d) 뷰 모델에 붙은 VFX(총구 화염·탄피·연기).

### 3.2 설계

- **같은 카메라, 같은 깊이 버퍼.** 뷰 모델은 물리 카메라(4절)로 세계와 함께 그린다(역 Z fp32 하나가 0.01 m~10 km를 덮는다: 근평면 1 cm 전역). 게임 관례인 **뷰 모델 전용 시야각**은 옵션(`viewModel.fov_override`)으로만 두고 기본은 끈다 — 켜면 뷰 모델의 화면 투영과 그 그림자·반사(진짜 기하로 계산)가 어긋나는 것을 조건으로 적는다(품질 표: 옵션 켜짐 = 그 항 정확성 포기, 게이트 밖). 벽 관통은 게임플레이(무기 내리기·충돌)의 몫이고 렌더러는 깊이 편향을 두지 않는다.
- **셰이딩·재질**: 일반 대역 A 픽셀(12.3). 조도는 화면 프로브의 캐시 항목 국소 반구 지도(2.5 결정 D)를 픽셀 법선에서 평가하므로 프로브 간격(16 px)이 손가락 곡률보다 성겨도 정확(조건: 항목이 뷰 모델 주변 공간을 대표 — 카메라 0.2~1 m의 캐시 항목은 카메라 주변 항목이라 항상 있음).
- **그림자(14.12 (1)(b) 확정)**: (i) **뷰 모델 전용 그림자 맵** — 태양 + 주 국소광 ≤ 2, 각 1024², 뷰 모델 경계 상자(≈ 1 m)를 1 mm 텍셀로, 매 프레임 재렌더(삼각형 100 k × 0.12 ns + fragment 1 M × 0.010 = 0.02 ms/광원) + SMRT 16탭(4.3 방식) penumbra; 캐스터 집합 = 뷰 모델 + 경계 상자 + 0.5 m 안의 세계 물체(벽에 손을 댐). (ii) 세계 캐스터(≥ 수 m)의 그림자는 보통 VSM 조회(클립맵 단 0: 텍셀 8 mm ≫ footprint이지만 penumbra 폭 ≥ 텍셀이라 정확 조건 성립). (iii) 접촉 그림자(손가락 사이, 1 mm 텍셀 한계)는 게이트 4의 뷰 모델 영역 |ΔL| 지표로 재고 한도 밖이면 4096²(0.25 mm, 0.3 ms) 또는 광선 자기 그림자(≈ 1 M px × 단거리 광선 0.36 ms). (iv) 뷰 모델 → 세계: 클립맵 단 0~2의 캐스터(dirty 페이지 ≤ 20, 0.02 ms) — 손 그림자가 땅·벽에 정확히.
- **반사·차폐**: 뷰 모델은 TLAS에 들어간다(스킨 BLAS refit 0.02 ms): 거울·물에 비친 손, 세계 반사 안의 뷰 모델, 뷰 모델 금속의 세계 반사(R 경로)가 모두 정확. 화면 공간 굴절(1절)의 유효성 검사도 뷰 모델을 그냥 기하로 본다.
- **애니메이션**: 캐릭터 경로(스킨 refit) — 애니메이션 모듈의 뷰 모델 리그(반동·흔들림은 애니메이션·게임플레이 값).
- **뷰 모델 VFX(조율 지시)**: 총구 화염 = 뷰 모델 소켓에 붙은 발광 스프라이트 시스템(0.A) + **구 광원**(0.A 7; 그림자 있는 국소광, 수명 1~3프레임, 손·벽을 비춤 — 매 프레임 전부 다시 그리기 기준이라 1프레임 광원도 같은 단가: 근거리 국소광 페이지 ≤ 100 × 페이지 래스터) + 연기(볼륨 입자 → 프록셀) + 탄피(메시 입자, 0.A 5) + 열 아지랑이(0.A 8). 화염이 뷰 모델 전용 그림자 맵의 광원이 되려면 주 국소광 슬롯 ≤ 2에 든다(우선순위 = 세기 × 근접).
- **1인칭 카메라 운동과 시간 적분**: 뷰 모델은 카메라와 함께 움직이므로 회전 블러(14.12 (2)(a))에서 **정지**(카메라 기준 속도 0)여야 한다 — 적분 영상은 세계 픽셀에만 적용(뷰 모델 픽셀은 vis id로 제외), 뷰 모델의 자체 운동(반동)은 (b) 속도 gather로.

### 3.3 비용식·품질·소유

| 항 | 값 [예상] | 조건 |
|---|---:|---|
| 전용 그림자 맵 ≤ 3광원 + SMRT | 0.06 + SMRT 0.02(뷰 모델 픽셀 1~2 M × 16탭 × 0.001) | 텍셀 1 mm; 접촉 그림자 게이트 |
| 세계 캐스터 몫(단 0~2 dirty 페이지) | 0.02 | 11절 행 안 |
| BLAS refit | 0.02 | 캐릭터 경로 |
| VFX(화염 광원·스프라이트·탄피) | 국소광 행 + 0.A 행 | |
| **합** | **≈ 0.10 + VFX** | 14.12 (1)과 같음 |

품질 정의(3절 표): 뷰 모델 그림자 행(14.12에서 추가됨), 시야각 옵션 켜짐 = 조건 기록. 게이트: 게임 벤치 모든 케이스에 뷰 모델 포함(RPP-1 케이스에 이미 있음), 거울 앞 뷰 모델 케이스 하나 추가 요청.

소유: V(뷰 모델 인스턴스 = 카메라 붙은 스킨 인스턴스, vis id 표시), S(전용 그림자 맵 + SMRT, 캐스터 집합 규칙), M(셰이딩·회전 블러 제외 마스크), R(TLAS·refit), FX(뷰 모델 VFX 소켓), 애니메이션(리그), RPP-1(뷰 모델 자산·케이스).

## 4. 물리 카메라 (노출 = 6절, 렌즈·시간 적분 = COVERAGE 14.12 (2); 여기서는 나머지 렌즈 모델과 통합 정의)

- **매개변수(저작·게임 스크립트)**: 센서 크기(36 × 20.25 mm), 초점 거리 f, 조리개 N, 초점 거리 s, 셔터 시간 t_s(기본 180° = 1/(2 fps)), ISO(노출 6절), 렌즈 모델 계수(아래). 시야각 = 센서·f에서 유도(RPP-1 manifest 형식).
- **렌즈 적분(피사계 심도)**: 14.12 (2)(c) — 착란원 C(z) = A f (z − s) / (z (s − f)) × (픽셀/센서 mm); 게이트는 핀홀(사용자 결정), 게임 벤치 "조준"과 사진 모드에서 켬(층별 적분 영상 0.2~0.3 ms, 전경 뒤 보케 가려짐 해제는 조건부 두 번째 층).
- **시간 적분(모션 블러)**: 14.12 (2)(a)(b) — 회전 적분 영상(고정비 0.4, 스트릭 > 16 px일 때) + 속도 gather + 조건부 t₁ vis buffer. 셔터가 열린 동안의 물체 운동은 물리 tick 보간(입자 렌더 규칙과 같은 상태 쌍)으로 정확.
- **렌즈 PSF(블룸·글레어·플레어; 13.1)**: 물리 모델 = 렌즈의 점 확산 함수(회절 + 수차 + 조리개 날 형상)를 HDR 영상에 컨볼루션. 정확 조건: PSF가 화면에서 이동 불변(shift-invariant)일 때 **FFT 컨볼루션**이 정확 — 1/2 해상도(1920×1080) HDR의 FFT 왕복 + PSF 곱: 2 M × log 21 × 3 채널 → [예상] 0.15~0.25 ms(FFT는 2.14의 물 FFT 커널 재사용); PSF는 저작(조리개 날 수·회절 스파이크·코팅 고스트의 대칭 성분). 비대칭 고스트(렌즈 플레어의 위치 의존 성분)는 광원 위치의 함수인 **스프라이트 고스트**(밝은 광원 ≤ 8개: 태양·국소광·발광 입자 중 세기 상위)로 = 외관 모델. 게이트: PSF 컨볼루션은 결정론·에너지 보존(PSF 합 = 1)만; 기준 영상은 PSF 없이(곡선 앞 HDR).
- **비네팅·색수차**: 물리 cos⁴ 비네팅 + 기계적 비네팅(저작 반경) — 픽셀당 곱 1(0); 횡색수차 = 채널별 방사 배율(저작 계수, 3탭) — 옵션(0.01 ms).
- **렌즈 오염(물방울·먼지, 1절 (e) 수면 교차 뒤)**: 화면 공간 굴절 오프셋 층(0.A 8과 같은 기계, 저작 텍스처 + 물방울 시뮬레이션은 VFX) — 외관 모델.
- **필름 그레인 등 연출 효과**: 게임별 선택, 결정론 해시 노이즈, 곡선 뒤 — 게이트 밖.
- **순서(셰이딩 커널 뒤 후처리 사슬, 전부 HDR에서)**: 시간 적분 → 렌즈 적분 → 렌즈 오염 오프셋 → PSF 컨볼루션(+ 고스트) → 노출·톤 곡선·그레이딩·비네팅·색수차·그레인·디더·인코딩(6절, 커널 안 또는 최종 패스). 셰이딩 커널이 "톤맵 뒤 4 B"를 바로 쓰는 2.11의 최적화는 **후처리 항이 켜진 경우 HDR 중간 버퍼(RGBA16F 66 MB, 별칭 풀)를 거친다**: 게이트(핀홀, 정지, PSF 끔)는 직접 쓰기 경로 그대로, 게임 벤치는 중간 버퍼 경로(+0.02~0.04 ms 읽기·쓰기).

비용 합 [예상]: 게이트 0; 게임 벤치 정지·보행 0.05~0.15(HDR 버퍼 + PSF 켤 때 +0.2); 회전·차량 케이스 +0.4~0.8; 조준 +0.2~0.3. 소유: M(후처리 사슬·PSF·곡선), core(HDR 버퍼·스왑체인), FX(렌즈 오염 시뮬), RPP-1(카메라 값).

## 5. 데칼과 표면 상태 (소유 M; VFX가 0.25 m 브릭 표면 상태를 CPU에서 생산)

### 5.1 정보량

세 종류: (a) **투영 데칼**(OBB 안에 재질 층 투영: 탄흔·핏자국·포스터·낙서; 저작 정적 + 실행 중 생성 ≤ 4 k 활성), (b) **메시 데칼**(데칼 재질을 가진 기하 = 일반 메시, 특별한 것 없음: 깊이 편향 대신 M 재질 레이어의 "표면 위 층" 규칙), (c) **표면 상태 장**(VFX 생산: 0.25 m 브릭마다 젖음·그을음·서리·먼지·핏자국 밀도 등 필드, 시간에 따라 이류·감쇠) — 재질 파라미터의 위치 함수(13.1 "날씨 반응 표면"과 같은 항).

### 5.2 설계

- **재질 해석 안에서 적용(M)**: 데칼은 G-buffer(8 B 팩 + 재질 표)에 굽지 않고 **재질 해석 단계에서 픽셀 재질을 수정**한다(레이어 재질 규칙 MATERIAL_LAYERS의 "위 층"으로 합성: 알베도·법선·거칠기·금속성·불투명도). 그래야 대역 B fragment 셰이딩(coverage)과 R hit 셰이딩도 같은 함수로 데칼을 받는다.
- **투영 데칼 목록**: 화면 타일 단위 OBB 컬링 — **S가 FroxelLists의 두 번째 프리미티브 형(OBB vs 프록셀 절두체 SAT)으로 제공**(S 12:40: 같은 목록 형식(헤더 first/count, 15-bit 색인), 별도 버퍼, M이 상한 ≤ 16을 정하고 S가 오버플로 수·오류 비트; 비용 [S 예상] 광원 목록과 같은 급(OBB 시험 ≈ 구-원뿔의 2배), M0 뒤 실측) → 타일당 데칼 ≤ 16 + 오버플로 비트; 픽셀마다 타일 목록을 걸어 월드 위치를 데칼 공간으로 변환, 내부 시험, 법선 각 페이드(법선 vs 데칼 축, 저작 각), 데칼 층 4탭(알베도·법선·거칠기·불투명), 우선순위·나이 순 합성. 비용 = 데칼 덮인 픽셀 × 데칼 수/픽셀 × 4탭 × 0.004 ns → 8.3 M × 30 % × 2 × 0.016 = **0.08 ms [예상]**; 파편·스킨 인스턴스에 붙은 데칼은 인스턴스 공간(인스턴스 변환과 함께 움직임, 목록 항목에 인스턴스 id).
- **광선 hit(R)**: 타일 목록은 화면 공간이라 hit 셰이딩에는 없다 → **데칼 AABB TLAS**(절차 AABB, ≤ 4 k, 갱신은 생성·소멸 때만; 집합체·입자 AABB BLAS와 같은 기계) — hit마다 질의 1회, any-hit 수집 ≤ 4 → R hit 수 × 0.05 ns [예상] ≈ 0.05 ms. 이것으로 반사·GI 안의 데칼이 정확하다(데칼 없는 반사는 조건 위반).
- **표면 상태 장(VFX 입력; 형식 확정 WORLD_VFX_DESIGN 10.4)**: 1 m 브릭 = 4³ 셀(0.25 m) × (unorm8 × 5: 젖음·그을음·서리·먼지·핏자국 + snow int16) + 헤더(key, t0_tick) = 464 → 512 B 페이지, 활성 ≤ 64 k = 32 MB, 변경 브릭만 업로드 ≤ 2 MB/tick, **감쇠는 셰이더가 t0_tick과 채널 반감기 상수로 해석 적용**; 브릭에는 **국소 deposit만**(튀김·발자국·핏자국·그을음·먼지·눈 제거) — 비·눈의 광역 젖음·쌓임은 노출도 × 날씨 스칼라(10절)로 재질 해석이 합성. 재질 해석이 픽셀 위치에서 브릭 1탭 + 노출도 1~2탭 → 젖음: 알베도 어둡게·거칠기 ↓ + 물 층(유전체 클리어코트, 1절 재질 클래스와 같은 프레넬), 서리: 결정 층(레이어 재질), 그을음·먼지: 알베도·거칠기 층, 핏자국: 색 층 — 전부 재질 레이어 규칙의 "위 층"이라 새 셰이딩 모델이 없다. 비용 8.3 M × 1탭 = 0.03 ms. 정확 조건: 상태 장은 0.25 m 해상도의 저작·시뮬레이션 값(물리 기준 없음) — 게이트는 결정론·연속성; 그 값이 만드는 재질은 레이어 규칙대로 정확.
- **데칼의 그림자·GI 영향**: 알베도 변경은 GI 캐시 갱신 광선이 hit 셰이딩에서 자동 반영(revision 불필요, 캐시가 수렴); 법선 데칼은 셰이딩만.
- **coverage fragment 위 데칼**: fragment 셰이딩이 같은 재질 해석 함수를 부르므로 풀·잎에도 표면 상태(젖음·서리)가 든다(타일 목록 걷기 비용 × fragment 수 — 상태 장 1탭은 싸고, 투영 데칼은 fragment에는 기본 끔(옵션): 잎 위 탄흔은 게임 요구가 아님).

### 5.3 비용·품질·소유

| 항 | 값 [예상] |
|---|---:|
| 타일 OBB 컬링 + 픽셀 목록 걷기 | 0.02 + 0.08 |
| 상태 장 브릭 1탭 + 노출도 1~2탭 + 층 합성 | 0.06~0.09 (World·VFX 정정) |
| 데칼 AABB TLAS 질의(R hit) | 0.05 |
| 상태 장 업로드 | ≤ 2 MB/tick(복사 큐, U 안) |
| **합** | **≈ 0.2~0.25 ms** |

품질: 투영·페이드·층 합성 = 재질 레이어 규칙(MATERIAL_LAYERS)대로 정확; 상태 장은 외관·시뮬레이션 값(결정론·연속성 게이트). 소유: M(재질 해석·목록·층·AABB 입력), VFX(상태 장 생산·형식·업로드), R(AABB TLAS 질의), core(데칼 인스턴스·World 행), S 또는 M(타일 컬링 기계 공유 결정: 광원 컬링 코드가 S면 S가 함수 제공).

## 9. 지형 — 높이장, 런타임 가상 텍스처, 재질 블렌딩, 구멍, 실시간 변형 (계획서 13.1; 소유 V·M·core, 물리 공유)

지금 설계의 지형은 정적 메시(BLAS 2.1 M 삼각형)뿐이다. 게임 레벨의 지형은 높이장이어야 한다(저작·변형·물리 공유).

- **표현**: 높이장 H(x, y)(예: 4 km² @ 0.5 m = 64 M 텍셀 R16 = 128 MB, 3단 스트리밍 타일 256²) + 구멍 마스크(비트, 동굴 입구) + 재질 가중 맵(텍셀당 재질 4 (id8 + w8) = 8 B) + **변형 텍스처** D(플레이어 주변 25 m, 5 cm 512², 높이 오프셋 + 법선; 물결 W와 같은 기계, 원천 = 물리 접촉 목록: 발자국·바퀴 자국·눈·진흙). 물리는 같은 H·구멍·D를 충돌에 쓴다. **D의 권위는 물리(World·VFX 설계 정정 13:10, WORLD_VFX_DESIGN 10.1):** 물리 충돌이 읽는 값은 권위 상태이므로 렌더 프레임(165 fps, 비결정)이 만들면 §2 계약(렌더는 committed 결과 소비, 권위 역기록 금지)에 어긋난다 → D는 tick 속도의 sim 슬롯 커널이 물리 접촉 목록(tick 커밋 사건 ≤ 1,024)에서 결정적으로 만들고(5~20 µs/tick [예상], 스냅샷 = 물리 아카이브 변경 타일) 렌더는 읽기만 한다; 눈 높이 변위만 렌더 전용(물리 무시, 눈 ≤ 10 cm 조건).
- **기하(V)**: 거리 기반 LOD 타일(64² 쿼드, 단마다 2배) — 메시 셰이더가 H·D 탭으로 정점을 만든다. **쿼드 크기 규칙: 투영 ≤ 4 px**(높이장 자체 해상도 0.5 m가 콘텐츠 정의이고, 그보다 고운 실루엣 정보는 없으므로 4 px 쿼드에서 1표본 vis + E 인구조사가 정확). 보이는 쿼드 ≈ 8.3 M / 16 = 0.5 M → 삼각형 1 M → **래스터 0.12 ms** + 정점 탭 1.5 M × 2 = 0.01. 구멍은 쿼드 컬링. 지형 실루엣은 대역 A.
- **재질(M) = 런타임 가상 텍스처(RVT)**: 블렌딩된 지형 재질(알베도·법선·거칠기·높이)을 가상 텍스처 페이지 캐시(페이지 256², 밉 사슬, 캐시 ≤ 4 k 페이지 = 1 GB… → 2.13b 텍스처 풀 안: 페이지 256² × 12 B = 0.8 MB → 512 페이지 400 MB [예상 상주])에 요청될 때 굽는다: 페이지 채우기 = 65 k 텍셀 × (재질 4 × 3탭 삼면 + 가중 1탭) 13탭 × 0.004 ns = 3.4 µs/페이지 → 이동 중 dirty ≤ 64 페이지/프레임 = **0.2 ms**(정지 0). 픽셀은 RVT 1탭(삼선형) + 페이지 표 간접 = 재질 해석의 다른 재질과 같은 비용. 정확 조건: 페이지 텍셀 ≤ 픽셀 footprint(VSM 텍셀 규칙과 같음; 요청 = footprint 기반 밉), 늦은 페이지는 저해상도 대체 없음(3단 규칙: 2.13b) — 페이지 요청 → 채우기 → 표본이 같은 프레임(간접 디스패치: 요청 목록 → 채우기 → 재질 해석) 또는 선반입(카메라 속도 × 3프레임).
- **변형(D)**: 메시 셰이더 변위 + 재질 해석의 압축·젖음(5절 상태 장과 결합: 눈 쌓임 = 상태 장의 눈 높이 → D에 더함). 비용 0.02(W와 같음).
- **광선·그림자·GI**: 광선용 BLAS는 가장 고운 정적 높이장 메시(스트리밍 경계에서 재빌드, 2.12 그대로; D는 BLAS에 없음 — 조건: 변형 깊이 ≤ 10 cm라 반사·GI 오차 ≤ footprint 급, 3절 표에 기록); VSM 캐스터 = 같은 LOD 타일(광공간 footprint 규칙); GI 캐시·프로브는 일반.
- **비용 합 [예상]**: 정지 0.13, 이동 0.35(RVT 채우기 포함). VRAM: H 128 MB(스트리밍 타일), RVT 캐시 ≈ 400 MB(텍스처 풀 상한 안), D 4 MB.
- **품질**: 높이장·재질 가중·RVT 텍셀 ≤ footprint 조건에서 정확; 변형은 BLAS 밖(조건). 게이트: RVT 페이지 대 직접 블렌딩(느린 경로) 동일성, 게임 벤치 지형 이동 케이스.
- **소유**: V(타일·메시 셰이더·구멍·D 변위), M(RVT 굽기·해석·재질 블렌딩), core(3단 스트리밍·페이지 캐시), 물리(H·구멍·D 공유·접촉 원천), World(저작·타일 원천).

## 10. 날씨 시스템 — 비·눈·안개·번개·바람장 (13.1; 렌더·물리·VFX·오디오가 같은 장을 소비)

- **바람장(World 소유, 전 모듈 소비)**: 전역 벡터 + 국소 영역(구·상자, 세기·방향·난류 = curl noise 매개변수) → 권위는 기존 World 필드 기계(NW_FIELD_WIND 레코드: 전역/구/상자·프레임·우선순위) + 난류 스키마(NW_COMPONENT_WIND_TURBULENCE 32 B), CPU·GPU가 같은 공유 헤더의 `windAt(x, t)`를 쓴다; GPU 3D 텍스처(64³ @ 8 m over 512 m, R16 ×3 = **1.57 MB**, 갱신 5~10 µs/tick)는 캐시이고 대역 조건 = 장 대역 ≥ 16 m(고운 난류는 입자의 해석 경로) — World·VFX 설계 정정 13:10. 렌더 소비: 식생 변위(기존 바람 항의 입력을 이 장으로), 입자(0.A 시뮬 힘), 천·머리카락(2.14), 물 표면 FFT 스펙트럼(풍속·방향). 비용: 식생 인스턴스당 1탭(기존).
- **비**: (i) 입자 — 늘인 스프라이트(0.A; 100~500 k, 카메라 주변 30 m 원통에 재활용), 조명은 입자당 태양·국소광 + 후방 산란 위상; (ii) **비 그림자 맵**: 위에서 아래로 보는 깊이 맵(정사영 512² 카메라 주변 128 m, 재렌더는 장면 변경·이동 시 ≤ 1/프레임 0.05 ms, 캐스터 = 대역 A 기하 + 집합체 T) → 비가 닿는 곳 판정(입자 소멸·물방울 튀김 원천·젖음 원천); (iii) 젖음 = **노출도(x) × 누적 스칼라 W(t)**(World 날씨 행: dW/dt = 강우 − W/τ_dry; 노출도 = 비 그림자 맵·하늘 가시성 탭) — 브릭 장에 쓰지 않는다(노출 면적 O(n) 권위 갱신·업로드 상한 회피; World·VFX 정정 13:10): 재질 해석이 wet = max(brick.wet, exposure_rain × W)로 합성, 웅덩이 = W × 지형 저지대 마스크(브릭 아님)의 물 층(유전체 클리어코트 → 반사는 1절 규칙: 잔잔 평면 → 평면 뷰 요청은 웅덩이 면적 A_r로 비용식); (iv) 물 표면 빗방울 = 물결 W 원천(무작위 임펄스, 강도 ∝ 강우). (v) 유리·렌즈 위 물방울 = 4절 오염 층.
- **눈**: 입자(스프라이트, 느린 낙하 + 바람장) + **눈 쌓임** = 노출도(하늘 가시성) × S(t)(World 날씨 행의 눈 높이 적분) − brick.snow_removed(국소 제거는 브릭), 경사 감쇠 → 재질 층(눈 재질, 서리) + 지형 D 변위(9절) + 메시 위 눈은 재질 층만(변위 없음: 조건 기록).
- **안개·매질**: 프록셀 매질(S)의 날씨 궤적 값(2.3 manifest) — 이미 설계됨; 국소 안개 볼륨(구·상자)은 프록셀 매질 목록(광원 목록과 같은 기계) 항목.
- **번개**: 광원(구 광원 또는 선분 광원, 1~2프레임, 세기 1e6 lux급, 그림자 있는 국소광 슬롯 우선 배정) + 볼트 = VFX 빔(FX 요청 8d) + 하늘 밝기(프록셀 in-scatter가 광원 항으로 자동) + 노출(6절 적응은 τ_b가 프레임보다 길어 화면이 하얗게 — 물리적으로 맞음; 게임이 원하면 저작 클램프).
- **오디오·물리 공유**: 같은 강우·강설·바람·번개 사건 값을 World 날씨 상태(tick 커밋)로 두고 모두가 읽는다.
- **비용 [예상]**: 비 입자 0.1~0.2(0.A 행), 비 그림자 맵 0.05, 상태 장 갱신 VFX CPU + 업로드 ≤ 2 MB/tick, 웅덩이 평면 뷰 A_r × 2.5(웅덩이 20 % 화면이면 0.5 — 수변 물 행과 같은 급), 번개 광원 = 국소광 행. **품질**: 비·눈 입자 = 0.A 정의; 젖음·눈 쌓임 = 상태 장(결정론·연속성); 웅덩이 반사 = 1절 규칙 정확.
- **소유**: World(바람장·날씨 상태), FX(입자·비 그림자 맵 소비·볼트), VFX(상태 장 갱신), S(매질·번개 광원 그림자), M(젖음·눈 층), V(지형 D).

## 11. 시간대 — 태양·달·별·대기 변화, 달빛과 밤하늘 (13.1; 소유 S, World 시간)

- **천체 위치**: 날짜·시각·위도·경도 → 태양·달 방향(천문 공식), 항성시 → 별 카탈로그 회전. 시간 속도 무제한(11절 기준 유지).
- **주 방향광 하나 규칙**: VSM 태양 경로는 방향광 하나다. 달 조도(보름 0.3 lux)는 낮 태양(1e5)의 3e-6, 시민 박명 하늘(10 lux)의 3e-2라 **태양 고도 < −6°(시민 박명 끝)에서 달이 태양 슬롯을 받는다**(그 전에는 달 그림자가 하늘광 아래 묻혀 보이지 않음: 정확 조건 = 달 조도 < 하늘 조도 × 1e-2; 전환 프레임에서 VSM 전부 다시 그리기 1회 = 기준 행 안). 태양·달이 동시에 보이는 낮의 달은 하늘 LUT의 발광 원반(그림자 없음, 조도 무시 — 조건 기록).
- **달**: 원반 = 태양이 비추는 램버트 구(위상 정확) × 알베도 텍스처(저작) → 하늘 뷰 LUT의 광원 항(J_ms는 매질만의 함수라 재사용; 달빛 스펙트럼 = 태양 반사라 약간 붉은 tint 저작 상수). 달빛 대기 산란·프록셀·VSM 전부 태양 경로 그대로(조도만 다름).
- **별·밤하늘**: 별 카탈로그(≈ 9 k, 등급 → 복사휘도, 색온도) 점 렌더(하늘 픽셀에 산포, 대기 소멸 T(θ) 곱, 픽셀보다 작은 점은 PSF(4절)로 퍼짐이 정확), 은하수·성운 = 저작 큐브맵(외관), 대기광·광공해 = 저작 하늘 복사휘도 바닥(외관). 비용 0.01~0.02.
- **낮·밤 노출**: 6절 자동 노출(EV −8~+16 범위), 표(LUT)는 fp16이라 1e-4 lux까지 상대 정밀 OK — 조건: 하늘 LUT의 최소 복사휘도 표현 > 별 배경(검증 항목).
- **품질**: 천체 위치·위상·달빛 대기는 물리(태양 경로와 같은 게이트, 달 케이스 1개: 보름밤 숲), 은하수·광공해는 외관. **소유**: World(시간·위치), S(천체 광원·하늘·별), M(노출 범위), RPP-1(밤 케이스).
- **볼류메트릭 구름(13.1 [기존])**: 재건 설계에는 없다 → 항목으로 추가: 구름 층(2~4 km 고도, 밀도장 = 저작 날씨 맵 + 3D 노이즈)을 **프록셀과 같은 적분 구조**로(하늘 뷰 LUT의 구름 층 march 64스텝, 태양 투과는 구름 층 광공간 깊이 맵, 다중 산란은 J_ms와 같은 종류의 층 표) — 정보량·비용식은 별도 절(13.1 다음 배치)로 쓴다. 지금은 빈칸 표시.

## 12. 광원 — 쿠키·IES·고보·광원 함수, 발광 메시 광원, 깜빡임·애니메이션 (13.1; 소유 M·S·R)

- **쿠키·IES·고보·광원 함수**: 델타(점·스팟) 광원의 방향별 세기 함수 f(ω)(2D 쿠키 텍스처, IES 1D/2D 각 프로필, 큐브/이중 포물면 고보, 절차 함수)를 12.4의 광원 식에 곱한다 — 델타 광원이라 **1탭 = 정확**(그림자 VSM 페이지는 f와 무관). 면광원(사각·원판·튜브·구)에 텍스처를 입히는 것은 닫힌 식(12.4)이 깨지므로 두 경로: (a) 저해상도 텍스처(≤ 8×8)의 **구분 상수 조각으로 나눈 면광원 합**(조각당 닫힌 식, 조각 ≤ 16: 비용 ×16), (b) 그 이상은 발광 메시 광원(아래). 비용: 광원당 픽셀 1탭 0.004 ns × ≤ 8 광원 = 0.03 ms.
- **발광 메시 광원**: (i) 반사·경면 = 12.4 구조 2의 발광 캐시 채널(있음); (ii) 확산 조명 = R의 GI 캐시 갱신 광선이 발광 삼각형을 **중요도 표본(발광 면적 × 세기의 누적 분포)** + MIS로 본다(13.1 [기존] 항목 — 재건 R에 있는지 확인 요청); (iii) 가까운 표면의 **날카로운 그림자**(네온 튜브 아래 벽)는 캐시(저주파)가 못 만든다 → 임포트 때 발광 메시가 단순 형상(사각·원판·튜브·구 근사 오차 ≤ 5 %)이면 **면광원 프록시 자동 생성**(그림자 있는 면광원 = 12.4 닫힌 식 + VSM 국소 페이지), 아니면 (ii)만. 정확 조건 기록: 프록시 근사 오차.
- **깜빡임·애니메이션**: 세기·색·위치·f(ω) 회전의 시간 함수(결정론 해시·곡선; 물리 카메라 셔터 안 적분은 프레임 상수 근사 — 조건: 깜빡임 주기 ≫ 1/165 s). 움직이는 광원의 페이지는 매 프레임 전부 다시 그리기 기준(11절)이라 추가 비용 없음.
- **품질**: 델타 광원 × f = 정확; 면광원 조각 합 = 조각 안 상수 조건; 발광 메시 = 캐시 + 프록시 조건. 게이트: C 경로추적기(쿠키·IES 텍스처 광원, 발광 메시)와 대조. **소유**: M(f 곱·조각 합·프록시 셰이딩), S(광원 페이지·프록시 슬롯), R(발광 중요도 표본·MIS 확인), 자산 파이프라인(프록시 생성).

## 13. 볼류메트릭 구름 (13.1 [기존]이지만 재건 설계에 없음; 소유 S)

- **정보량**: 구름 층(고도 1.5~4 km, 두께 ≤ 2 km) 밀도장 ρ(x) = 날씨 맵(2D: 덮임·종류·고도, 저작·바람 이류) × 3D 노이즈(Perlin-Worley 옥타브, 최소 특징 ≈ 50~100 m) × 높이 프로필. 카메라에서 본 구름 복사휘도 L_c(ω)는 방향의 2D 함수이고 산란 때문에 부드럽다: **각 대역 조건 = 노이즈 최소 특징의 투영 ≥ 4 px**(3 km에서 100 m = 1.9° = 120 px, 성립) → 1/4 해상도에서 정확.
- **설계**: (i) **구름 광공간 투과율 맵** T_c(태양 방향 정사영, 가시 하늘 영역 512², 텍셀마다 층 관통 32스텝 밀도 적분; 0.0011 ns/스텝 [브릭 march 단가] → 262 k × 32 = 0.01 ms) — VSM 투과율 층과 같은 종류; 지면 receiver는 태양 가시성에 T_c 1탭을 곱한다(구름 그림자, 8.3 M × 0.004 = 0.03). (ii) **하늘 픽셀 march**(1/4 해상도 960×540, 하늘 픽셀만 ≈ 0.25 M): 층 슬랩 안 64스텝(날씨 맵의 거친 min/max로 빈 구간 건너뜀), 스텝마다 밀도 2탭(날씨 2D + 노이즈 3D) + 태양 단일 산란(T_c 1탭 × 위상 HG 이중 로브) + **다중 산란 층 표 J_c**(반평면, 밀도·g별; J_w와 같은 빌더) + 하늘 조도(대기 LUT의 위·아래 반구 조도) → 0.25 M × 64 × (3탭 0.012 + ALU) ≈ **0.2 ms**; 전해상도 업샘플은 깊이 인식(전경 기하 가장자리). (iii) 대기 원근: 구름 거리 d에서의 대기 투과·in-scatter(대기 LUT의 거리 축)로 합성 — 구름은 대기 안이므로 하늘 뷰 LUT의 "무한 거리" 값을 구름 뒤 하늘에만 쓴다. (iv) 반사·프로브: 하늘 뷰(구름 포함)가 하늘 복사휘도 원천이라 반사·GI가 자동으로 구름을 본다. (v) 시간: 날씨 맵 이류(바람장)와 태양 이동은 프레임마다 그대로 계산(이력 없음 = 태양 속도 무제한 규칙과 일치).
- **비용 [예상]**: T_c 0.01 + march 0.2 + 그림자 탭 0.03 + 업샘플 0.02 ≈ **0.26 ms**(구름 있는 날만; 맑음 0). VRAM: 날씨 맵 4 MB, 노이즈 3D 32 MB(128³ × 2), T_c 1 MB, J_c 0.5 MB.
- **품질**: 밀도장에 대한 단일 + 층 다중 산란(J_c ε 게이트 = J_ms와 같음), 1/4 해상도 대역 조건, T_c 텍셀 규칙(≤ 지면 픽셀 footprint의 태양 투영 — 구름 그림자는 부드러워 조건 완화 가능: 반그림자 폭 ≥ 텍셀). 게이트: C 경로추적기에 **불균질 매질(ratio tracking)** + 같은 밀도장 → 구름 케이스(낮·황혼).
- **소유**: S(전부), World(날씨 맵 저작·이류), C(매질 추적).

### 14.1 유리(Glass 클래스, A10) — 정의·비용식·품질 (렌더 A 설계, 2026-09-26; V 투과 층 v1.67 위에서)

**정의(8.1에 넣을 모델, M·R·C 같은 식).** 유전체 경계면이다. 굴절률 η = `ior`, 거칠기 r(α = max(r², 1e-4)의 GGX), 흡수는 틴트 c = baseColor다. Fresnel은 편광 평균의 정확한 유전체 식(WaterShading.hlsli의 `waterFresnel`과 같은 식; Schlick 아님)이다. 두 형태가 있다(저작 규약: Unity `_UnravelGlass`, `_ThinWalled`).
- **얇은 판**(`twoSided` = 1, 창유리): 두께를 기하로 갖지 않는 평행 판. 한 번 지날 때 투과율은 t = c다. 판 안의 다중 반사를 닫힌 식으로 더한다.
  - R_p(θ) = F + (1 − F)² F t² / (1 − F² t²)
  - T_p(θ) = (1 − F)² t / (1 − F² t²), F = F_d(cos θ; η)
  - 매끈하면 반사는 거울 방향이고, 투과는 방향이 그대로다(판 두께만큼의 평행 이동은 기하에 두께가 없으므로 0 — 정의).
  - 거칠면 반사는 GGX(α) 로브이고, 투과는 두 면을 지나는 굴절 로브다. 방향 분포 폭은 소각 근사로 α_t ≈ 2 (η − 1) α / η다. 이 근사는 C가 판 기준(두 면 미세면 적분)과 잰다.
- **속찬 물체**(`twoSided` = 0, 병·블록): 닫힌 메시의 부피다. 들어갈 때와 나갈 때 두 번 굴절한다(스넬, 전반사 포함). 부피 안 흡수는 exp(−σ_a d)이고 σ_a = −ln(c) / 0.01 m(틴트 = 1 cm 투과)다. 부피 안 다중 내부 반사는 전반사 경로까지 포함해 기준(C)이 정의다.

**실시간 경로(주 뷰; V의 투과 층 translucentVis·Depth·Class와 coverage 투과 기록).**
1. **표면 반사**(두 형태 공통): M이 유리 표면에서 태양 원반·국소광의 스펙큘러(유전체 F, 판이면 R_p의 F 자리)를 셰이딩한다. 간접 반사 복사휘도는 R이 투과 층 픽셀에 대해 반사 작업을 만든다(아래 요청 R-1). 합성 값은 R_p(또는 F) × L_refl이다.
2. **투과**:
   - 매끈한 얇은 판: T_p × L_behind(픽셀)이다. L_behind = 대역 A 셰이딩 + 그 뒤 기록 합성이며, 방향이 그대로이므로 **정확**하다(조건: 판이 평면이거나 곡률 반경 ≫ 판 두께 — 정의상 두께 0이라 항상 성립).
   - 거친 얇은 판: L_behind를 투과 로브의 화면 원판으로 적분한다. 반경 = 뒤 표면까지의 거리 × tan(α_t)의 투영 px이다. A5 피사계 심도와 같은 원판 gather 기계(깊이 순 층, 탭 = min(C²/4, 64))를 쓴다.
   - 속찬 물체: 굴절 광선을 **R 광선**으로 추적한다(요청 R-2: 입구 굴절 방향으로 물체 BLAS 안에서 출구를 찾고, 출구 굴절 방향으로 장면을 맞혀 셰이딩, 전반사면 내부 반사 1~2회까지). 화면 공간 경로는 뒤 면을 모르는 한 정확하지 않으므로 쓰지 않는다.
3. **합성**: 투과 클래스 1(표본 하나가 픽셀 전체)은 그 표면 하나로, 클래스 2는 투과 기록을 깊이 순으로 앞에서 뒤로 누적한다(C·transmittance). 투과 기록은 합집합을 채우지 않는다(v1.67 규칙).
4. **그림자**: 유리를 지난 태양·국소광은 T_p(판) 또는 입구·출구 Fresnel·부피 흡수(속찬 물체)를 곱한다. 색 그림자다. S의 VSM은 깊이 하나라서 투과 캐스터에 따로 "투과 깊이 + 투과율" 한 층을 둔다(요청 S-1). 코스틱(병이 모으는 빛)은 사진 모드(기준 추적기)에만 있고 실시간 정의 밖이다(조건 기록).

**비용식 [예상]** (P_t = 투과 층 픽셀 수; 4K 창 하나가 화면 20 %면 P_t = 1.66 M):
- 표면 셰이딩(태양·국소광·유전체 F): P_t × 0.02 ns = 0.03 ms.
- 반사 R-1: P_t × C_refl(R의 반사 경로 분류, K/G/M). 매끈한 판은 M 경로 광선 1.68 ns → 창 20 %면 2.8 ms. 평면 창은 평면 반사 카메라(2.6, 이미 있는 비용식 A_r × 2.5)가 싸다: 창 20 %면 0.5 ms. 경로 선택은 R의 비용식이다.
- 투과:
  - 매끈한 판은 L_behind 읽기 1회 → P_t × 0.01 = 0.02 ms.
  - 거친 판은 원판 gather로 P_t × 탭 × 0.025 ns → 반투명 유리(α 0.3, 뒤 2 m, 원판 ≈ 40 px, 탭 64)가 화면 20 %면 2.7 ms. 이 경우는 A5와 같은 층별 적분 영상(0.2~0.3 ms)으로 간다.
  - 속찬 물체는 P_solid × (2 ~ 4 광선 × 1.68) → 병 몇 개(화면 1 %, 83 k px)는 0.3~0.6 ms.
- 그림자 S-1: 투과 캐스터 페이지 × 기존 VSM 캐스터 비용(투과 캐스터가 있는 페이지만).

**품질 정의·게이트.** 기준은 C 경로추적기의 유전체 BSDF(판: 두 면, 속찬: 부피, 같은 η·틴트)다(요청 C/E-1: 기준 추적기에 Glass 클래스).
- 매끈한 판의 투과·반사 가중(R_p, T_p)은 정확이다. 게이트 = 판 뒤 영상 × T_p와 기준의 relMSE가 3절 반사 한도 안.
- 거친 판은 α_t 근사다(C 측정).
- 속찬 물체는 R 광선 경로의 내부 반사 차수 상한(2)이 조건이다(그 이상은 전반사 갇힘 빛, 에너지는 흡수로 처리 — 차이는 C 측정).
- 게이트 장면: 창 하나 + 병 하나 + 태양(창 그림자, 병의 굴절).

**요청 목록.**
- R-1: 투과 층 픽셀의 반사 작업(법선·거칠기 = 투과 표면; F는 M이 곱한다).
- R-2: 속찬 유리 굴절 광선(입구 → 출구 → 장면, 전반사 2차까지).
- S-1: 투과 캐스터의 색 그림자 층.
- C/E-1: 기준 추적기 Glass BSDF.
- V: 추가 요청 없음(v1.67의 투과 층·기록으로 충분).
- M(내 몫): 표면 셰이딩, R_p·T_p, 합성, 거친 판 gather(A5와 공유).

## 15. 블렌드 셰이프와 정점 애니메이션 텍스처 GPU 평가 (13.1; 소유 V·애니메이션·R)

- **블렌드 셰이프**: 셰이프 N개의 희소 델타(정점 색인 + Δ위치 fp16 ×3 + Δ법선 oct16 = 12 B) → 메시 셰이더가 스킨 전에 활성 셰이프(가중 ≠ 0)의 델타를 더한다: 얼굴 20 k 정점 × 활성 30 셰이프 = 0.6 M 덧셈 ≈ 0.01 ms; 가중치는 애니메이션 모듈 tick 값 + 프레임 보간. 스킨 BLAS refit(캐릭터 경로)에 델타 적용 뒤 정점을 준다(정확).
- **정점 애니메이션 텍스처(VAT)**: 구운 시뮬레이션(천·파괴 사전 시뮬·군중)의 프레임별 위치(+법선) 텍스처, 정점당 1탭(프레임 보간 2탭), BLAS refit 동일. 메모리 = 정점 × 프레임 × 8 B(예: 10 k × 300 = 24 MB, 3단 스트리밍 자산).
- **품질**: 정의대로 정확(보간 = 선형, 조건: 프레임 간격 ≤ 1/60 s). **소유**: V(메시 셰이더), 애니메이션(가중·재생), R(refit), 자산 파이프라인(굽기).

## 16. 표시 — 입력→화면 지연, VRR, 프레임 페이싱 (13.1; 소유 core·I, 측정 하네스)

- **지연 사슬(165 fps)**: 입력 표본 → 게임 tick(60 Hz)과 **프레임 시각 카메라**(시점 회전·이동은 tick이 아니라 프레임마다 최신 입력으로 갱신: (f) 제출 경로의 보간 상태 위에 프레임 카메라를 얹음 — 물체 상태는 tick 보간, 카메라는 프레임 최신) → 렌더 6.06 ms → present. 목표 지연 = 입력 → present ≤ 1 프레임 + 렌더(≈ 12 ms). 측정: 입력 타임스탬프 → `IDXGISwapChain::GetFrameStatistics`/present 통계, 하네스 열(I)로 기록.
- **프레임 페이싱**: 대기 가능 스왑체인(`SetMaximumFrameLatency(1)`, waitable object)로 큐잉 1프레임 상한; CPU 제출은 GPU 완료에 맞춰(프레임 그래프 제출 시각 = 직전 프레임 GPU 시작 + 예산); 프레임 시간 분산은 **VRR**(48~165 Hz 범위, tearing 허용 플래그 + DXGI_PRESENT_ALLOW_TEARING)이 흡수하고 고정 주사율 표시에서는 165의 약수 제한기(설정 층).
- **Unity 호스트**: present는 Unity 스왑체인(I 경계) — 렌더러 프레임 완료 펜스 → Unity present; 두 프레임 큐잉 금지는 I가 Unity 설정(QueueDepth)로 보장.
- **비용**: 없음(정책). **품질**: 지연·페이싱은 게이트 항목(게임 벤치에 "입력→present" 열 ≤ 12 ms, 프레임 시간 P99 ≤ 6.06 + 0.5).
- **소유**: core(스왑체인 정책·제출 시각), I(Unity present·큐 깊이·측정 열), RPP-1(게임 벤치 열).

## 17. 사진·시네마틱 모드 = 기준 경로추적기 위에 (엔진 범위 항목; 소유 C·core·I)

- **정의**: 게임 안에서 일시 정지 → 자유 카메라 → **C 트랙 GPU 경로추적기**(사용자 승인, 조율 12:00 결정으로 CPU 기준 → GPU 전환 중)가 같은 장면(커밋된 World 스냅샷·같은 재질 정의·같은 매질·같은 카메라 모델)을 점진적으로 렌더한다. 렌즈·시간 적분은 정확 표본화(조리개·셔터, 물체 tick 보간), 노출·곡선은 6절과 같은 사슬. 이것이 "기준 모드"의 유일한 자리다 — 실시간 경로에 낮은 품질 모드를 두지 않는다는 규칙과 일치한다.
- **정보량·비용**: 표본/픽셀 N(사용자가 정함; 4K 1 spp ≈ 25~50 ms 디스패치 조각, GPU 잠금 슬라이스 ≤ 15 s 규칙과 같은 조각 구조), 수렴 표시(relMSE 추정), 디노이즈 없음(정의상). 저장: EXR(선형 HDR) + 곡선 뒤 PNG.
- **정확 조건**: 실시간 렌더러와 같은 정의(재질·매질·카메라·광원)를 쓰므로 게이트 도구와 같은 코드 경로 — 사진 모드가 곧 사용자 눈으로 보는 게이트다.
- **소유**: C(경로추적기·조각 디스패치·수렴 표시), core(일시 정지 스냅샷·카메라 UI 훅), I(Unity 쪽 사진 모드 UI·저장).
