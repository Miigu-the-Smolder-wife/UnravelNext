# 요청: 대형 월드 원점 재설정 (렌더 C, C9; World 경계 = 엔진 1) — 2026-09-26

## 1. 정의

- 렌더러의 월드 좌표는 float32다. World(엔진 1)는 double로 위치를 가지고, 렌더러에 보내는 값은 `월드 좌표 − 원점 O`다. O는 호스트가 정하고 **1024 m 격자점**만 쓴다(애니메이션 `na_instance_rebase`와 같은 격자, 커밋 c37dd71e).
- 원점이 O에서 O' = O + Δ로 바뀌는 프레임(Δ는 1024 m의 정수배, 각 축)에 호스트는 **(a) 그 프레임의 모든 변환을 새 원점 기준으로 보내고 (b) `FrameContext::originShift = Δ`를 준다.** 렌더러의 모든 월드 좌표 상태(이전 변환, 이전 뷰, 월드에 붙은 캐시)는 같은 프레임에 −Δ만큼 옮겨진다.
- **품질 조건(정확):** 원점 재설정 프레임의 영상은 재설정이 없었던 경우와 같다 — 이력(움직임 벡터, VSM 페이지, GI 캐시, 반사 누적, 입자)이 끊기지 않는다. 판정: 같은 장면을 원점 A에서 그린 N프레임과, 중간에 원점을 A → A + Δ로 바꿔 그린 N프레임의 영상 차이가 원점 A + Δ에서 처음부터 그린 경우와의 차이와 같은 범위(부동소수점 반올림) 안.
- **왜 1024 m인가:** 캐시 격자가 모두 2의 거듭제곱 m이고 1024 m 이하이므로(VSM 페이지 0.125 × 2^k m, k ≤ 13; GI 셀 ≥ 0.0625 m; 절차 풀 셀 8 m; 인스턴스 청크 셀 64 m) Δ가 모든 격자의 정수배다 → 캐시는 **정수 격자 이동**으로 옮겨지고 재계산이 없다. 1024 m를 넘는 격자(VSM 14단 이상)는 그 단의 페이지만 다시 그린다(프레임 비용식에 "전부 다시 그리기"가 이미 있음).
- **비용 [예상]:** 재설정 프레임에 GpuScene 인스턴스 표 재업로드(I × 144 B, 10만 인스턴스 14 MB → 복사 0.03 ms), VSM 페이지 표 이동(페이지 표 크기, < 0.01 ms), GI 해시 재색인(항목 20만 × 64 B 읽고 쓰기 → 0.05 ms), 정적 TLAS 재빌드(R: 비동기, 스트리밍 경계와 같은 경로) — 재설정은 드물다(1024 m 이동마다, 60 m/s에서 17 s마다).

## 3. 게이트

- `origin_rebase_is_seamless`(V·통합): 움직이는 카메라 32프레임, 16프레임째에 Δ = (1024, 0, −2048) 재설정 — 재설정 경로 영상 대 처음부터 새 원점 영상: V 깊이 비트 동일, 최종 영상 차이 ≤ 두 원점 기준 영상끼리의 반올림 차이.
- 큰 좌표 정밀도: 원점에서 100 km 떨어진 장면을 재설정 없이 그리면 깊이·정점 떨림이 보이고(float 해상도 7.8 mm), 재설정하면 원점 근처와 같다 — 문제와 해결을 같은 시험이 보인다.
