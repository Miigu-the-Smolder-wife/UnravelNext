# 요청: 뷰 id별 시간 이력과 영속 리소스 (A14 → 모든 트랙) — 2026-09-26

A14(렌더 텍스처 카메라, 거울, 포털, 분할 화면; FEATURES_GAME 8)는 한 프레임에 주 뷰 말고도 전체 파이프라인을 도는 보조 뷰를 여럿 그린다. 뷰 DAG는 렌더 A와 합의했다(아래 1절). 각 트랙은 지금 "주 뷰" 하나에 묶인 시간 이력과 영속 리소스를 **뷰 id별**로 나눠야 한다. 이 문서는 그 규칙이다.

## 1. 합의된 틀 (렌더 A·C)

- `FrameContext::auxViews`: 항목마다 { `id`(호스트가 정하는 안정 키), `ViewDesc`, kind, 출력 텍스처, reads[] }. kind는 RenderTexture(조준경·감시 카메라, 선형 HDR 출력), Mirror(임의 평면), Portal(짝 변환 카메라 + 포털 영역 마스크), Split(분할 화면, viewport 사각형에 표시 인코딩)이다.
- FrameRenderer는 reads로 위상 정렬해 보조 뷰를 주 뷰 **앞에** 기록한다. 순환 간선(거울 속 거울, 포털 쌍)은 직전 프레임 출력을 읽는다.
- 각 보조 뷰는 주 뷰와 같은 트랙 호출을 거친다. 이미 있는 ViewKind::PlanarReflection 경로(R의 평면 반사)는 그대로다.
- 재질은 텍스처 색인 비트 31로 "뷰 출력"을 가리킨다(방출·기본색 슬롯, 렌더 A).
- `ViewResources::viewId`: 주 뷰 0, 보조 뷰는 FrameContext의 id. 트랙은 이 값으로 자기 상태를 찾는다.

## 2. 트랙이 지켜야 할 규칙

1. **시간 이력은 뷰 id별이다.** 앞 프레임 값을 읽는 모든 상태를 `viewId`로 나눈다. 예: V의 HiZ·coverage 영속 버퍼·이전 카메라 위치, R의 반사 누적·스크린 프로브 이력, M의 노출 적응, S의 뷰별 프록셀 이력, FX의 뷰별 정렬·이력.
2. **세계 캐시는 공유한다.** 뷰와 무관한 세계의 정보(VSM 물리 페이지, GI 월드 캐시, 브릭, 텍스처, 물 장, 입자 시뮬레이션)는 뷰마다 복제하지 않는다. 뷰별 요청(VSM 페이지 요청 등)은 합쳐서 한 번 처리한다.
3. **크기나 형식이 바뀌면 그 뷰의 영속 리소스를 다시 만든다.** 뷰의 너비·높이·출력 형식이 앞 프레임과 다르면, 그 뷰 id의 영속 리소스와 이력을 모두 새로 만들고 이력은 불연속으로 다룬다(렌더 A의 U2 초록 사각형 결함이 이 규칙을 어긴 경우다). 호스트가 한 렌더러에서 뷰 크기를 바꾸는 경우도 같다.
4. **사라진 뷰의 상태는 풀어 준다.** framesInFlight + 1 프레임 동안 기록되지 않은 뷰 id의 영속 리소스는 해제한다(GPU가 아직 읽을 수 있는 동안은 지연 해제).
5. **불연속은 뷰별이다.** 보조 뷰가 처음 나타나거나, 카메라가 끊기거나, 3이 적용되면 그 뷰만 이력을 버린다. 다른 뷰의 이력은 그대로다.
6. **이력이 없는 뷰도 정확해야 한다.** 첫 프레임은 이력 없이 정의대로 그린다. 기존 규칙(불연속 = 정확한 새 시작)과 같다.

## 3. 비용과 VRAM

- 뷰마다 P_v × 0.30 ns + 0.05 ms(FEATURES_GAME 8). 1024² 조준경 하나 ≈ 0.35 ms [예상].
- 뷰별 트랜지언트는 해상도 비례로 별칭 풀에 합산된다. 뷰별 영속 이력은 각 트랙이 자기 표에 "뷰당 바이트 × 해상도" 행으로 적는다(ARCHITECTURE 2.13b).
- 보통 PC(8 GB VRAM) 규칙은 그대로다. 뷰 수와 해상도는 게임이 정하는 저작 예산이고, 품질 정의는 바뀌지 않는다.

## 4. 소유와 순서

- 렌더 C: FrameContext·FrameRenderer의 뷰 DAG(렌더 A 허락), V의 뷰 id별 상태, A14 시험·게이트.
- 렌더 A: M의 Split 뷰별 post·노출 이력, FrameConstants `viewOutputs`, 재질의 뷰 출력 판독.
- 각 트랙: 2절 규칙을 자기 상태에 적용하고, 자기 트랙 상태 문서에 뷰별 상태 목록과 뷰당 VRAM을 적는다.
- A14 시험은 주 뷰 + 보조 뷰 2개(서로 다른 크기)로 이력 분리와 크기 변경 재생성을 확인한다. 각 트랙의 뷰별 상태가 없으면 그 트랙의 출력이 주 뷰 이력으로 오염되는 것이 시험에서 드러나도록 짠다.
