# 요청: M0 게임 기능을 위한 렌더러 기능 (I 트랙, 2026-09-26; 게임플레이 설계 GAMEPLAY_DESIGN_KO.md 4·5·8.2·8.4·12.3)

## 왜 필요한가

사용자 결정으로 첫 목표는 M0 "게임 개발 시작 최소선"이다(재구축 계획 14.5). 완료 조건은 다음 흐름이다: 가져온 에셋으로 1인칭 레벨을 만든다 → 편집 모드와 플레이 모드의 Game 뷰를 새 렌더러로 그린다 → 1인칭으로 걷는다 → 물체를 밀어 쓰러뜨린다 → 래그돌 → 충돌 입자 → 저장·불러오기.

게임플레이 설계 세션과 호스트 경계를 맞추면서 렌더러에 없는 것이 다섯 나왔다. 호스트 ABI는 I가 이어 붙인다.

## 요청

1. **commit 뒤 인스턴스 추가·제거** (가장 급하다).
   - 지금은 commit에서 인스턴스 집합이 고정된다. 편집 모드 Game 뷰에서 물체를 놓거나 지우는 것, 게임 중 스폰, 파괴 조각, soft body·Matter 표시가 모두 여기에 걸린다.
   - 지금 호스트는 재구성(전체 재 commit)으로 우회한다. 레벨이 커지면 편집 한 번에 수 초가 든다.
   - 요청하는 것:
     - 용량을 둔 인스턴스 풀에서 add/remove를 GpuScene 프레임 갱신(6.3)처럼 처리한다.
     - 제거한 인스턴스 번호는 재사용하지 않거나, 재사용 규칙을 명시한다.
     - 새 메시(BLAS·클러스터)를 늦게 추가하는 경로도 필요하다. 이미 적재된 메시의 인스턴스 추가가 먼저다.
2. **재질 갱신과 셰이더 핫 리로드** (편집 반영).
   - `UnxSceneUpdateMaterial(index, desc)`: commit 뒤 재질 값·텍스처 바꾸기. 재질 revision과 장면 revision 규칙은 GpuScene::setMaterialTextures와 같다. GI 에포크가 바뀌는 것도 받아들인다.
   - 셰이더(커널) 다시 적재: `UnxShaderReload(paths[])`. 편집 중 셰이더 반복 작업용이다.
3. **뷰 모델 층**(1인칭 무기·손).
   - 인스턴스 플래그 `VIEW_MODEL`: 정점 투영을 p' = P_world⁻¹ · P_vm · p로 다시 매핑한다(별도 FOV). 깊이 버퍼는 하나다. 설계 COVERAGE 14.12가 기준이다.
   - 프레임에 뷰 모델 FOV를 넘긴다.
   - 뷰 모델은 세계에 그림자를 드리우지 않는다. 받는지는 설계가 정한다.
4. **주 뷰 숨김 플래그**: 1인칭 캐릭터의 머리처럼, 주 뷰에서는 안 보이지만 그림자·반사·GI에는 남는 인스턴스다.
5. **물리 카메라 셔터 구간**: [t_f − 1/330 s, t_f]. 모션 블러가 들어올 때 쓴다. 표본 시각이 구간의 끝이고, 미래 자세는 없다. 지금은 계약 값만 둔다.

## 호스트 쪽(I)

- ABI: 인스턴스 add/remove, 재질 갱신, 셰이더 다시 적재, 인스턴스 플래그 둘, 프레임 필드(뷰 모델 FOV, 셔터 구간)를 선택 export와 구조체 version으로 붙인다.
- 브리지:
  - 장면 적재기(`UnravelNextScene`)가 편집 변경을 재구성 대신 add/remove/갱신으로 바꾼다.
  - 카메라 리그 → 뷰 모델 루트(애니메이션 NA_PRESENT_ROOT_EXTERNAL) 경로를 둔다.
