# 요청: 렌더 이력 불연속(World 복원·카메라 컷)의 계약 (I 트랙, 2026-09-25)

## 왜 필요한가

이전 엔진 시험 `WorldHierarchySkinAndVfxReachRealRenderedPixelsAcrossRestore`(NativeAnimation EditMode)는 "World를 스냅숏으로 되돌리면 같은
tick의 출력 이미지가 원래와 바이트 단위로 같다"를 요구한다. World 세션이 5회 반복으로 좁혔다: 복원 전후 World 행(Transform, WorldAffine,
SkinMatrix, 모프)은 5/5 비트 동일한데 픽셀이 다르다. 원인은 렌더 쪽이다(옛 TitanNative의 시간 누적·GPU 스킨 원자 순서). 옛 렌더러는
퇴역하므로, 새 렌더러가 이 계약을 어떻게 지킬지 정해야 한다.

새 렌더러의 사실[실측]:
- 시간 상태가 있다: GI 월드 캐시(200k 항목, 항목당 이력 최대 32), 반사 이력, 화면 프로브, VSM 페이지 캐시, 이전 프레임 변환(움직임).
- 실행마다 결정적이지 않다: GI 캐시 갱신이 원자 순서에 기대므로 같은 장면·같은 입력의 직접 실행 두 번이 64프레임에서 P99 약 300/1023
  다르다(`unx_test_host_hostabi` 메모, 2절). 두 확률 셰이딩 항(GI 프로브 조도, 반사 입사; `shading.experiment_disable = 6`)을 빼면 ABI 경로와
  직접 경로의 프레임이 비트 동일하다.
그래서 "(a) 시간 상태 재설정"도 "(b) 렌더 상태 스냅숏·복원"도, 그 뒤 프레임의 계산이 결정적이지 않으면 바이트 동일을 보장하지 못한다.

## 원하는 변경

1. **호스트 신호(I가 ABI로 넘긴다):** 프레임마다 이력 불연속 비트. `FrameContext::historyDiscontinuity`(또는 같은 뜻의 필드).
   - `Restore`(World 스냅숏 복원, 분기 변경) / `Cut`(카메라 순간 이동·컷).
   - 호스트는 안다: committed World의 `NW_Info` epoch·branch가 바뀌거나 tick이 뒤로 가면 복원이다(`nw_snapshot_previous`도 이 쌍을 끊는다).
     I 어댑터가 그 프레임에 비트를 켠다.
2. **렌더러의 동작(코어·트랙):** 불연속 프레임에서 모든 시간 상태를 초기 상태로 되돌린다. GI 캐시·반사 이력·화면 프로브는 비우고,
   VSM 캐시는 전부 무효로 하고, 그 프레임의 prevObjectToWorld = objectToWorld(움직임 0), 이전 뷰 = 현재 뷰로 둔다. 이것이 (a)다.
   (b) 렌더 상태 스냅숏은 GPU 메모리 100 MB 이상을 복사하고, 이후 프레임이 결정적이지 않으면 이득이 없어서 제안하지 않는다.
3. **같음의 수준(계약으로 정할 것):**
   - **결정적 부분집합은 비트 동일:** 확률 항을 뺀 품질(시험용 사본)에서, 재설정 뒤 같은 입력 열이면 같은 프레임은 비트 동일하다.
     지금도 성립하는 것으로 보인다(HostAbi 패리티). 코어가 계약으로 확인해 달라.
   - **전체 렌더러:** 둘 중 하나로 정해 달라.
     - (i) 결정적 누적. GI·반사·프로브 갱신을 원자 순서에 기대지 않는 고정 순서 축약으로 바꾼다. 그러면 재설정 뒤 같은 입력 열이 비트 동일한
       이미지를 낸다. 재현·디버깅·복원 계약에 가장 강하다. 비용은 코어·R이 식으로 따진다.
     - (ii) 허용 오차. 재설정 뒤 K프레임에 복원 이미지와 원래 이미지의 차이가 "재설정 뒤 독립 실행 두 번"의 차이(실측 바닥) 이하다.
       지표는 C의 기준 비교 도구다.
   I는 (i)을 권한다. 최고 품질 방향에서 결정성은 복원·리플레이·네트워크 동기화·회귀 시험의 바탕이다.

## I 쪽 할 일(계약이 정해지면)

- ABI: `UnxFrameSetDiscontinuity(r, flags)`(다음 큐 패킷으로 모음, 떨어진 패킷의 비트는 다음 것으로 OR).
- 데이터 월드 어댑터: 복원·분기 감지 → Restore 비트. 카메라 컷은 게임 코드 API(`UnravelNextRenderer.MarkCut()`).
- 시험 이전: 옛 시험을 UnravelNext 경로로 옮긴다. (1) Unity 없는 렌더러 시험: 장면 A로 N프레임 → 재설정 → 같은 입력 N프레임을 그리고 결정적
  부분집합이 비트 동일한지(그리고 (i)이면 전체가 비트 동일한지) 본다. (2) Unity EditMode 시험: 데이터 월드 스냅숏 → 변경 → 복원을 거쳐
  같은 tick 이미지가 같은지 본다. 수준은 3에서 정한 대로다. (2)의 World 고정물(fixture)은 NativeAnimation 시험의 것을 쓸 수 있는지 World와 맞춘다.
