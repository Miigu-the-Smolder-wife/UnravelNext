# 요청: VSM dirty 페이지를 하드웨어 깊이 아틀라스로 그리기 (S 트랙, 2026-09-25; V 래스터 서비스 5.3 확장)

## 왜 (실측)
- 태양이 매 프레임 바뀌면(시간대, 빠른 게임 하루 k ≥ 12) 요청된 VSM 페이지가 모두 dirty다.
- 실측[city_block, GpuLock, `--sun-deg-per-s 30`]:
  - 4K: dirty 3,598 페이지/프레임, T_sun 2.1 M 삼각형. 래스터 5.56 ms, clear 0.46, pagemax 0.71, S 합 9.43 ms.
  - 1440p: dirty 1,887, 래스터 3.58 ms, S 합 6.30 ms.
- 설계식 T_sun/30G(0.07 ms)가 틀린 이유: 비용이 삼각형이 아니라 텍셀 fragment에 비례한다. 페이지마다 128² = 16,384 텍셀이 원시 버퍼 풀에 `InterlockedMax`(S 픽셀 커널 `VsmPagePixel`)로 쓰인다.
  - 4K 전부 다시 그리기는 59 M fragment 이상(겹침 포함)이다.
  - fragment당 약 0.09 ns [실측 환산].
- 하드웨어 깊이 테스트(ROP, 압축·조기 Z)는 원자 UAV 쓰기보다 fragment당 훨씬 싸다(c_rop는 마이크로벤치 대상).

## 원하는 변경 (V)
- `DepthRasterRequest`에 **타일 아틀라스 모드**를 추가한다. 이름 예: `tileAtlas` = { BufferRef slots; uint32_t atlasTilesPerRow; }.
  - 조건: `tileLocal`과 `cullMask`가 있고 `depthTarget`이 유효해야 한다.
  - 타일 국소 래스터가 켜진 타일 하나를 그릴 때, 그 타일 사각형을 아틀라스 슬롯의 사각형으로 옮겨 그린다.
    - 슬롯 = `slots[뷰의 cullMaskOffset 기준 타일 번호]`.
    - 아틀라스 위치 = (슬롯 % atlasTilesPerRow, 슬롯 / atlasTilesPerRow) × cullTilePx.
    - 뷰포트·가위는 그 슬롯 사각형이다. 투영은 원래 타일 위치에서 슬롯 위치로 평행 이동한다. 정점 단계의 2D 오프셋이라 깊이는 같다.
  - fragment는 `depthTarget`(D32, 아틀라스)에 하드웨어 깊이로 쓴다. 픽셀 커널은 없거나 바람 메타 기록용 얇은 것이다(아래).
  - 한 클러스터가 여러 켜진 타일을 덮으면 타일마다 한 번씩 그린다(지금 타일 국소의 "켜진 타일 구간마다"를 타일마다로 나눈다).
- 바람 메타(페이지에 그린 바람 캐스터의 scale 최대값): 깊이만 쓰는 모드에서는 픽셀 커널이 없다. 그래서 V가 클러스터 단위로 "이 타일에 그린 인스턴스" 목록을 내거나, 요청자 픽셀 커널을 깊이와 함께 허용한다(early-Z 뒤 실행). 둘 중 V가 싼 쪽을 고른다.

## S 쪽 (V 구현 뒤)
- dirty 페이지마다 아틀라스 슬롯을 준다(dirty 목록 순서). 아틀라스는 transient D32이고 크기 = ⌈dirty / 64⌉ × 64 슬롯 × 128²다(4K 전부 다시 그리기 3,600 슬롯이면 8192 × 7,296 텍셀, 약 240 MB). 부족하면 여러 번 그린다.
- 아틀라스를 지우는 비용은 깊이 fast clear라 거의 0이다(지금의 `s.vsm.clear` 0.46 ms를 대체한다).
- 옮기기 + 블록 계층: 페이지마다 컴퓨트 그룹 하나가 아틀라스 128²를 읽어 높이로 인코딩해 풀에 쓰고, 같은 그룹에서 VsmPageMax의 블록 계층을 만든다(지금 0.71 ms 패스를 흡수).

## 비용식 [예상]
- 래스터: F_sun × c_rop + 클러스터 제출(지금과 같음). c_rop는 마이크로벤치로 잰다.
- 옮기기와 블록 계층: dirty × 16,384 × (4 B 아틀라스 읽기 + 4 B 풀 쓰기 + 블록 32 B/64 텍셀). 4K 전부 다시 그리기면 0.5 GB / 700 GB/s ≈ 0.7 ms. 지금 clear 0.46 + pagemax 0.71 = 1.17 ms를 대체한다.
- 합(4K 전부 다시 그리기): ROP 항 + 약 0.7 ms + 제출 약 0.9 ms. 지금은 6.54 + 1.17 = 7.7 ms다.
- 실제 태양 속도는 S의 단 기저 분할 갱신(S_STATUS 7절)으로 dirty가 약 1/12이 되어 이 비용도 그만큼 준다.

## 마이크로벤치 요청 (코어 `Tools/Microbench` 또는 설계 개정 세션)
- 128² 타일 3,600개에 삼각형 2 M개(도시 캐스터 분포)를 그린다: (a) UAV 원자 max(지금), (b) D32 아틀라스 ROP. fragment당 ns와 전체 ms를 잰다.
