# 게임 벤치 장면 (2026-09-26)

사용자 결정(조율 전달): 사용자의 게임은 1인칭이고 물리 개체가 많으며 그래픽은 가볍다. RPP-1 한 세계·경로·봉인은 보류하고, 게임 부하 기준의 물리 중심 벤치를 먼저 만든다. 렌더러 설계 목표(RPP-1 비용식)는 그대로다.
표기: [실측] 실행 결과, [예상] 설계·유도 값.

## 1. 부하 윤곽 (사용자 답)

| 항목 | 값 |
|---|---|
| 시점 | 3D 1인칭(눈높이), 1인칭 뷰 모델(손·도구) 슬롯 |
| 목표 | 4K 165 fps(렌더 6.06 ms), 권위 tick 60 Hz. 1440p도 함께 잰다 |
| 물리 | 동시에 움직이는 개체 ≤ 1,000(파편 포함). 종류 전부: 강체(상자·잡동사니), 관절·래그돌·차량, 천·로프·soft, 파괴·파편·유체 |
| 그래픽 | 평범한 지형·건물, 광원 수십 이하, 표준 재질. 가까운 물체의 셰이딩·그림자, 모션 블러, 피사계 심도는 제대로 켠다 |

## 2. 도구와 변형

`build/RPP/bin/unx_gamebench.exe --out Cache/GameBench --preset all` (CPU만, 7개 수 초 [실측], 같은 입력이면 출력이 바이트 단위로 같다 [실측])

| 변형 | 움직이는 개체 | 생성(파편 상한 제외) | 파편 상한 | 렌더 재생 강체 | 유체 입자 |
|---|---:|---:|---:|---:|---:|
| fp_250 | 250 | 187 | 63 | 236 | 0 |
| fp_500 | 500 | 375 | 125 | 473 | 0 |
| fp_1000 | 1,000 | 750 | 250 | 948 | 0 |
| fp_1000_fluid32k / 64k / 128k / 250k | 1,000 | 750 | 250 | 948 | 32,768 / 65,536 / 131,072 / 250,000 |

매개변수(`--name --objects --fluid --destruction-per-minute --fragments --debris-share --seed --duration`)와 종류 비율(`GameBenchMix`: 상자 0.30, 잡동사니 0.30, 파괴 가능 0.20, 래그돌 0.05, 차량 0.02, 경첩 0.03, 천 0.04, 로프 0.04, soft 0.02). 파편 상한 = 개체 수 × 0.25, 생성 개체 = 개체 수 − 상한이라 **최대 동시 움직임 ≤ 개체 수**다. 파괴 사건 분당 12회(파편 16개/회, 수명 20 s, 상한에서 오래된 것부터 사라짐).
출력(변형마다): `gamebench_<이름>.unxscene`(환경 + 강체), `gamebench_<이름>_bodies.json`(C 형식 1: 강체 부분의 운동학 재생 + 질량·마찰·반발), `gamebench_<이름>.json`(매개변수, 개체 전부, 사건, 카메라, 빈칸), `gamebench_index.json`(해시). 같은 입력 = 같은 출력(결정적 RNG 스트림).

## 3. 장면

- 320 × 320 m 마당: 가운데 120 m 평탄(놀이 영역), 바깥 둔덕, 동서 도로 ±155 m(차량 케이스), 남북 도로, 창고 6동(콘크리트 + 골강판 지붕), 비계(기둥 4 + 6 m 보: 로프·천이 매달림), 유체 통(안쪽 2.5 × 2.5 m, 벽 1.2 m; 물리 설계 9절 요청 "수 m³": 250k = 3.9 m³ → 깊이 0.62 m, 상자 4개가 6 s마다 떨어짐), 연못(x −15..15, z −70..−52, 깊이 3 m, 수면 Water 클래스: 물 케이스).
- 광원 24(그림자 8: 창고 벽 투광등 스폿 30,000 cd; 나머지 16은 도로 가로등 구). 태양 고도 40°, 맑은 대기, 바람 2 m/s. 재질은 표준(흙·아스팔트·콘크리트·강철·목재·벽돌·플라스틱·고무·도장).
- 구역: A(x −45..−10, z −45..−10) 상자 더미(3×3·4×4 피라미드) + 20 % 낙하; B(10..45, 10..45) 잡동사니(통·판자·벽돌·작은 상자·양동이·병), 원통의 절반은 옆으로 굴러감; C(−44..−12, 11..54) 파괴 가능(기둥·벽판·상자) + 파편 풀 + 결합 그래프 벽 1(요소 200, 8 × 3 × 0.3 m, 47 s에 파괴) + 실행 중 CARVE 기둥 1(평면 8, 35 s); D(15..35, −40..−15) 비계와 물탱크; 도로 z ±2 차량(차체 + 바퀴 4, 6~12 m/s). 래그돌은 중앙 반경 14~30 m.

물리 카메라(사용자 결정 11:20, 설계 전달): **셔터 180° = 1/330 s(165 fps)**, 조리개는 aim 말고 모두 핀홀(json `fNumber` 0). 센서 36 × 20.25 mm(16:9), 세로 화각 = 2 atan(10.125 / f)(18 mm → 58.7°, 24 mm → 45.7°). 표본마다 위치·방향·yaw·pitch·초점 거리·f값·초점(m)·세로 화각·컷을 json `camera.samples`에 둔다. 컷은 50 s(차량), 60 s(물) 두 번이다.

뷰 모델(설계 14.12 가정): 팔 + 소총(MotusMan v55 팔, MCO `M4_Rifle_01`), 카메라에서 0.2~1 m, 삼각형 ≤ 100 k, 스킨, 재질 2~4(금속 포함), 세계에 그림자, TLAS 포함. 자산 가져오기 대기, 렌더러 기능은 P8.

## 5. 실행 (지금 되는 것)

렌더러 강체 부분만: `GpuLock.ps1 -Track I -- build/I/bin/unx_gate_host_hostdynamic.exe --scene Cache/GameBench/gamebench_fp_1000.unxscene --characters 0` — I의 게이트가 형식 1 파일을 그대로 읽는다(I 확인). 이 실행은 I 빌드 폴더의 실행 파일이라 I 세션이 돌리거나 게이트 worktree 빌드로 돈다. 카메라 케이스 재생은 게이트에 카메라 트랙 입력이 생긴 뒤다(지금 게이트는 장면 카메라 0 고정).

전체(모든 물리 종류 + 뷰 모델 + 카메라 효과)는 Unity Player 데이터 World 실행기(이전 저장소 `Assets/RPP1/GameBench`, 아직 없음)가 레시피로 개체를 만들고 카메라를 재생해야 한다(6절 빈칸).

## 7. 결과 JSON (`gamebench-result 1`, `Results/RPP/GameBench/<이름>_<빌드>.json`)

```text
{ "format": "gamebench-result 1", "bench": "<이름>", "benchSha256", "sceneHash", "build": { commit, dirty, quality SHA-256, driver },
  "gpuLock": holder, "contended": { seconds, frames },
  "runs": [ { "resolution": "3840x2160" | "2560x1440",
              "cases": { "<케이스>": { "gpuFrameMs": { median, p95, p99, max }, "frames": N } },
              "gpuFrameMs": { median, p95, p99, max },               // 전체 경로
              "cpuTickMs": { "physics", "animation", "world", "vfx", "total": { median, p95, p99 } },  // 워커 합산, tick마다
              "memory": { "vramMB": { peak, median }, "ramMB": { peak, median } },
              "counts": { "movingObjectsPeak", "bodies", "debrisPeak", "fluidParticles", "lightsVisible" } } ],
  "verdict": { "target4KMs": 6.06, "gpuP95Within": bool, "tickHz": 60, "tickP99WithinPeriod": bool } }
```
물리 기록(물리 설계 요청): 유체는 dx(5 cm)·셀당 입자(8)·substep(2)·정렬 주기(4)·활성 셀·GPU 클럭 고정 여부·tick당 GPU ms(P2G·G2P·정렬·격자)·VRAM; 파괴는 결합 수·요소 수·평면 수·파편 수(강체/입자)·절단 tick CPU ms·잠들 때까지 tick당 ms; soft는 정점·구속·반복·substep(json `objects[].params`에 설계값); 활성 강체 수(NP `active_bodies`)는 tick마다. 모든 수는 [실측]이다(실행 결과만 적는다). 유체 훑기는 변형 네 개의 `cpuTickMs.physics`·`memory`·(렌더가 생기면) `gpuFrameMs`와 영상 캡처를 한 표로 묶어 사용자에게 보인다.
